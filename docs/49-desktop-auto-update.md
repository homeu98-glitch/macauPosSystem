# 49 · 桌面 App 一鍵更新（熱更新 + 覆蓋安裝）

> 配套：`docs/47`（桌面 Companion 代理）、`docs/48`（Desktop Shell 架構）。
> 代碼：`desktop-companion/`（Electron 殼）、`src/components/app-update-panel.tsx`（POS 內面板）、
> `src/app/api/desktop-release/route.ts`（版本資訊 API）、`public/releases/`（託管安裝包）。

## 0. 先講清楚：你已經有「桌面 App」了

根據 `docs/48`，你嘅需求「用 Desktop App 把網頁包起來、模擬成獨立桌面應用」**已經實作**：

- `desktop-companion/electron/main.js` —— Electron 殼，`BrowserWindow` 直接 `loadURL(Vercel)`，
  網頁本身**唔落 exe**。
- `desktop-companion/electron/preload.js` —— 暴露 `window.companionShell` 俾網頁叫原生功能。
- `npm run dist` 產 `Macau-POS-Desktop-Setup-x.y.z.exe`（NSIS 安裝檔）。

所以使用者雙撃 exe 就開到一個「似足獨立 App」嘅窗口，**入面係你嘅 POS 網頁**。
呢部分已經係「熱更新」：你改網頁 → `git push` → Vercel 重建 → 用家下次開 exe 自動係新版，**完全唔使重打包**。

**唯一要重打包嘅情形**：Electron 殼 / 打印代理（companion）本身改動（例如加 USB/BT、改端口）。
呢啲先需要「檢查更新」拉新安裝包覆蓋安裝。本文件就係講呢個閉環。

## 1. 更新方案總覽

```
┌─ Macau POS Desktop (Electron exe) ───────────────────────┐
│  main process                                              │
│   ├─ electron-updater（autoDownload=false）                │
│   ├─ tray「檢查更新」                                      │
│   └─ IPC: check-update / download-update / quit-and-install│
│                                                            │
│  BrowserWindow → Vercel POS 網頁                           │
│   └─ AppUpdatePanel（顯示版本 / 檢查 / 下載 / 安裝）        │
└───────────────────────────────┬──────────────────────────┘
                                 │ 1) checkForUpdates()
                                 ▼
              https://macau-pos-system.vercel.app/releases/latest.yml
                                 │ 2) 有新版 → downloadUpdate()
                                 ▼
              https://macau-pos-system.vercel.app/releases/
                                 │    Macau-POS-Desktop-Setup-x.y.z.exe
                                 ▼
                  3) NSIS 覆蓋安裝 → 4) quitAndInstall() → 重啟
```

**發佈後端 = Vercel static**（`public/releases/`），唔使額外開 server / S3 / GitHub Releases。
`electron-updater` 嘅 generic provider 直接讀 `latest.yml` + exe。

## 2. 版本資訊來源（manifest.json）

`public/releases/manifest.json` 係版本單一事實來源：

```json
{
  "version": "0.1.0",
  "pubDate": "2026-08-23T12:00:00Z",
  "releaseNotes": "初始版本：Electron 殼 + 內嵌打印代理 + 自動更新",
  "fileName": "Macau-POS-Desktop-Setup-0.1.0.exe",
  "sha512": "<auto-generated by release script>",
  "path": "/releases/Macau-POS-Desktop-Setup-0.1.0.exe",
  "url": ""
}
```

- `src/app/api/desktop-release/route.ts` 讀呢個檔，加 `downloadUrl` 返 JSON（俾 POS UI / 將來手動下載用）。
- `latest.yml` 係 `electron-builder` 自動產（由 `package.json` version 決定），release script 會將佢同步去 `public/releases/`。

## 3. 發佈流程（一鍵）

改完 companion / Electron 殼之後：

```bash
cd desktop-companion
npm install                 # 首次 / 加依賴才要
npm run release -- --patch  # 或 --minor / --major / --ver 0.3.0
```

`scripts/release.mjs` 會自動：

1. bump `desktop-companion/package.json` version
2. 跑 `electron-builder --win nsis` → 產 `dist/*.exe` + `dist/latest.yml`
3. 計 sha512 完整性校驗
4. 複製 exe + `latest.yml` 去 `../public/releases/`
5. 更新 `../public/releases/manifest.json`
6. 清走舊版 exe（只留當前版）

然後你 commit + push：

```bash
cd ..
git add public/releases/ desktop-companion/package.json
git commit -m "release: desktop v0.1.1"
git push                    # Vercel 自動部署 → /releases/ 對外可見
```

用家 APP 內撳「檢查更新」就會拉到 `v0.1.1` 嘅 exe。

## 4. 用家端體驗（AppUpdatePanel）

POS 網頁（喺 Electron 內開）嘅「設備設定」頁會顯示：

| 狀態 | 顯示 | 用家動作 |
|---|---|---|
| idle | 版本 x.y.z · 就緒 | 撳「檢查更新」 |
| checking | 檢查中… | 等 |
| available | 版本 x.y.z → v新 · 有更新可用 | 撳「下載更新」 |
| downloading | 下載中 42% + 進度條 | 等 |
| downloaded | 已下載，可安裝 | 撳「安裝並重啟」 |
| latest | 已是最新版本 | 無 |
| error | 更新失敗 | 撳「重試」 |

- **非 Electron 環境**（普通瀏覽器開 Vercel）面板自動隱藏——網頁更新唔使理。
- 首次開 APP 3 秒後自動探一次更新（prod only）；有更新會 push 狀態去面板，用家自行決定裝。
- tray 右鍵選單都有「檢查更新」。

## 5. 關鍵代碼位

| 職責 | 檔案 | 說明 |
|---|---|---|
| 更新狀態機 | `desktop-companion/electron/main.js` | `setupAutoUpdater()` 註冊 `update-available / download-progress / update-downloaded` 事件 → `pushUpdateStatus()` 經 IPC 推去網頁 |
| 觸發下載 | `electron/main.js` `ipcMain.handle("download-update")` | 用家撳「下載」→ `autoUpdater.downloadUpdate()` |
| 安裝重啟 | `electron/main.js` `ipcMain.handle("quit-and-install")` | `autoUpdater.quitAndInstall()`（NSIS 覆蓋） |
| 網頁橋接 | `electron/preload.js` | 暴露 `checkUpdate / downloadUpdate / quitAndInstall / onUpdateStatus / getVersion` |
| 網頁 UI | `src/components/app-update-panel.tsx` | 版本對比 + 進度條 + 三粒按鈕（檢查 / 下載 / 安裝） |
| 版本 API | `src/app/api/desktop-release/route.ts` | 讀 manifest 返 JSON（含 downloadUrl） |
| 發佈 | `desktop-companion/scripts/release.mjs` | bump + build + 複製 + 更新 manifest |
| 發佈配置 | `desktop-companion/package.json` `build.publish` | `generic` provider，url=`https://macau-pos-system.vercel.app/releases/` |

## 6. 限制 / 注意

- **冇真·hot-patch**：Windows 落緊嘅 exe 被鎖，唔能原地替換 binary。「更新」= 落 installer → NSIS 覆蓋 → 重啟，係必然，唔係缺陷。
- **網頁要網絡**：Vercel 網頁要連網先載到（你要「更新只 push 網頁」即係接受呢點）。
- **程式碼簽署**：正式發佈建議加 code-signing cert（`build.win.certificateSubjectName` / `cscLink`），否則用家會見 SmartScreen 警告。未簽嘅 exe 仍然裝得，只係彈警告。
- **macOS / Linux**：`release` script 只跑 `--win nsis`；要跨平台要各自 build（electron-builder 支援，但 NSIS 只 Windows）。
- **首次 build** 會下載 Electron binary（~80MB），要網絡 + 耐啲。

## 7. 開發模式試更新

```bash
# 1) 起一個 local static server 託 /releases/（或用 Vercel preview）
# 2) dev 版強制開更新：
ELECTRON_UPDATE_DEV=1 npm start
# 3) 改 package.json version → 跑 release script 產檔 → 對應 url 要有 latest.yml
```

`app.isPackaged` 為 false 時 `setupAutoUpdater()` 會 skip；設 `ELECTRON_UPDATE_DEV=1` 先會試。
