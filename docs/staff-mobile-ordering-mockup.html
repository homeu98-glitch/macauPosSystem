設計說明（畀評審睇）

枱況三態

由 pos_orders 未結單即時計算，唔另建表。
綠色＝空枱（撳入去填人數開新單）
橙色＝用膳中（撳入去載入現有單加菜）
紅色＝即將結帳（標示金額，仍可加菜）
灰色＝暫停使用

售罄處理

灰化保留，唔隱藏。店員可以向客人講「呢款賣晒，要唔要換第二款？」，比一片空白菜單好用。
灰化同時劃走菜名，避免誤撳。

送出後自動流程

POST /api/pos/sync（帶 POS 憑證）
→ 寫 pos_orders（已授權分支）
→ 建 pos_print_jobs（廚房單）
→ 中繼機 60 秒內 claim 出紙

手機端不負責三件事

不直連打印機　無藍牙、無網段要求
不收款結帳　waiter 角色無此權限
不印客人小票　小票由收銀台結帳時出

🔴 關鍵安全點

店員單帶 POS 終端憑證 → 走「已授權」分支，天然繞過匿名白名單（ANONYMOUS_ALLOWED_SOURCES）。
切勿把 "staff" 加入白名單 —— server client 用 service_role 繞 RLS，加錯等於開放匿名偽造店員單。
