二、逐頁 Wireframe 描述

S1 · Landing Page —「你是會員嗎？」

區塊內容規格
品牌區Logo + 主標「你是會員嗎？」+ 副標說明主標 23px / 800；副標 13px 灰
店舖標識綠點 + 店名 · 枱號（或「快餐」）掃碼取 ?store= / ?tableId=；Kiosk 取裝置綁定
主按鈕 ①👤 是，我是會員橙色實心 · 高 58px
主按鈕 ②🙋 不是，直接點餐半透明描邊 · 高 58px（**同等份量**，唔可以做得細）

狀態：本頁無錯誤態、無載入態（資料已由 bootstrap 提供）。若 store 參數無效 → 顯示「此 QR 碼無效」並隱藏兩個按鈕。

S2 · 會員登入

欄位 / 按鈕規格驗證規則
會員帳號inputMode="numeric" · 高 54px · 17px 粗體正規化後 /^\d{8}$/（不加 +853）
PIN 碼type="password" · 同上尺寸/^\d{4}$/
登入並繼續點餐橙色 · 高 58px兩欄皆合法才可用（否則灰）
忘記 PIN？到前台處理描邊 · 高 44px顯示指引，唔做任何 API 呼叫
🔴 錯誤訊息必須統一
「帳號不存在」、「未設 PIN」、「PIN 錯誤」三者**一律**顯示同一句 「帳號或 PIN 不正確」—— 否則可被用來枚舉邊個電話號碼係會員（契約 §4.5.2）。

PIN 唔會經過前端運算：只原樣傳去 POS 伺服器，由伺服器用 AUTH_PIN_PEPPER 派生 Auth 密碼。前端 bundle 唔可以出現 pepper。

S3a / S3b · 登入失敗與鎖定

態觸發畫面
S3a 失敗驗證失敗（1–4 次）PIN 欄轉紅框 + 「帳號或 PIN 不正確（剩餘 N 次機會）」+「重新登入」
S3b 鎖定連續 5 次失敗鎖圖示 + 「請 14:52 後再試」+ 主按鈕變灰顯示倒數 + 「改用非會員直接點餐」
網絡失敗請求逾時底部橫幅「網絡連線失敗，請重試」+ 按鈕保持可用

鎖定維度＝「電話號碼」跨 IP 生效（唔可以只靠 IP，例如店內共用 NAT 會誤傷全店）。

S6a / S6b · 付款方式選擇

選項標題副標
①💳 扣會員儲值餘額「餘額 MOP 258.00 → 扣款後 MOP 188.00」（即時算埋扣後值）
②🏪 到前台支付「到收銀台以現金／電子支付結帳」
態行為
S6a 餘額足夠兩個選項皆可選；預設選「扣餘額」
S6b 餘額不足頂部紅色提示卡顯示差額；「扣餘額」變灰但保留可見；自動改選「到前台支付」

為何 S6b 唔可以似 S4 咁直接隱藏：S4 係「根本冇呢個能力」，S6b 係「有但今次用唔到」。客人要見到「點解唔得」同「差幾多」。

S7a / S7b · 確認扣款（PIN 再確認）

態條件畫面
S7a 需 PIN距登入成功 > 180 秒顯示金額 + 扣後餘額 + PIN 輸入框 + 「確認扣款」+「取消，改為到前台支付」
S7b 免 PIN距登入成功 ≤ 180 秒同上但無 PIN 欄，加一句「你剛於 3 分鐘內登入」
🔴 180 秒窗口係唯一防線（Ledger Q5 拍板）
  • 3 分鐘係「建議」唔係強制 —— 由 POS 自己實作。
  • 起計點＝登入成功（唔係上次 PIN 確認）。
  • 範圍＝時間內全部免（唔係「每張單一次」）。
  • refresh token 唔可以延長呢個窗口。
  • Ledger 端完全唔會再驗 PIN。
手機被盜 = 180 秒內可扣錢，所以呢個閘寫錯 = 等於冇二次確認。

S9b 網絡失敗逾時／結果不明「請勿重複操作」+「系統會自動核對，唔會重複扣款」「重試」·「改為到前台支付」
🔴 「結果不明」係最危險嘅態
Ledger 唔提供 lookup 接口（Q6）→ POS 無法查「到底扣咗未」。 唯一手段係用同一冪等鍵重試（會回同一 txnId）。 絕對唔可以把「查唔到」當成「未扣款」→ 會導致重複扣錢。 唔確定就引導去前台由店員核對。
