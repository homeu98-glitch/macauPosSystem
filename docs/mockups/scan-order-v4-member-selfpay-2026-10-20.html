⑧支付安全規則 必打 PIN · 餘額不足 · 紅線
自助結帳要做到幾嚴？
必打 PIN（今次重點）
而家 scan 端有 免 PIN 窗口：登入後 180 秒內（loggedInAt+pinWindowToken，use-kiosk-order.ts:101/112/1340/1687-1692）撳「確認扣款」都唔使打 PIN。J 要取消 —— 會員自助結帳一律入 PIN。
改法：mobile 端 `MemberPaySheet` 死都顯示 PIN 板（pinFreeAgoLabel 唔再用）；commit 唔帶免 PIN 票 → server 自然回 `pin_required`。
Kiosk（店內平板）可以保持 180 秒方便版（共用裝置、店員喺側）—— 要確認。
餘額唔夠（已有）
現有流程：報價／扣款時 server 回餘額不足 → 客人可「改為到前台支付」，訂單保留唔使重新點（`payInsufficient`+`switchPayToCounter`）。
唔做「餘額＋現金」部分支付（要對數邏輯複雜，一次過扣先乾淨）—— 沿用現行。
沿用嘅保護
連錯 5 次 PIN 鎖 15 分鐘；鎖咗仍然可點餐，到前台付款。
扣款用 quote（不扣錢）→ commit 冪等；網絡斷咗結果未知就顯示「結果未知＋重試同一張報價」（現有 S9 保護）。
交易編號 = 對帳憑據；額外小票欄位支援補助。
個資紅線（§7.2）
· 「手機綁單」記嘅係 session / orderId，唔記電話、唔記姓名
· 「記住會員」只存 token 或 customerId（uuid），餘額每次由伺服器換先渲染
· 電話俾晒後台驗證，唔顯示、唔落機
