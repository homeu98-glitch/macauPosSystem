### 9. 客人掃碼誤判「已落單」（用戶掃 A01 枱面「空間 / 已坐 0/10」卻被擋）
- **根因**：`fetchUnsettledKioskOrder` 舊邏輯用「該 tableId 有任何 server-side open 單」＝「有人坐」；`reopened` / `paid` counter / 其他 terminal `draft` 撞到 tableId 就會誤擋客人。
- **修正（src/lib/kiosk-order.ts）**：resume 嘅單一真源改為「客人自己嘅單」—— 用 `sessionStorage["kiosk-last-order"]` 配 server-side 對應 ID，**且只認 `source === "scan"`**。`tableId` fallback 永遠 return null（保留參數做 call site 簽名穩定，但唔再用佢做判定）。
- 新增 `isCustomerScanOrder()` predicate，文件化「resume 對象」嘅定義。
- 影響：
  - ✅ 客人第一次掃（sessionStorage 空）→ 正常落單
  - ✅ 重複掃 + 單未 terminal → resume 顯示明細
  - ✅ 重複掃 + 單已 settled → null，客人可落新單
  - ✅ 掃到 stale reopened / 商戶單枱 → null，唔再被誤擋 ← bug fix
- tsc --noEmit 只餘 layout.tsx LayoutProps 假陽性。
