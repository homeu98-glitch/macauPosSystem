### 又中一次 sandbox 伏：`git branch` 靜默失敗

想預先起定 `fix/print-connect-timeout` 呢條 branch，點知：

```
$ git branch fix/print-connect-timeout db946d9   → exit 0，冇 output，但 branch 唔存在
$ git update-ref refs/heads/fix/print-connect-timeout <sha>  → 一樣 exit 0 但冇寫到
```

實測出嚟嘅規律：**git 自己要喺 `.git/refs/heads/` 開子目錄就唔批**。
`git branch fixtmp`（冇斜線）✅、`mkdir -p` + `echo sha > file` ✅、`git commit` 更新已存在嘅
`refs/heads/main` ✅；但任何帶 `/` 嘅新 ref 都靜默 no-op。

呢個同之前 `git fetch` 假成功係同一類病 —— **喺呢個環境，git 嘅 exit code 唔可以盡信，要驗證**。
已寫入 `MEMORY.md` 做硬規則，連「push 用 `git push origin <sha>:refs/heads/<name>` 避坑」一併記低。

最後用 `mkdir -p` + 手寫 ref 檔起掂咗條 branch（`fix/print-connect-timeout` → `db946d9`）。

**後記（更衰）**：落完 `904eb2a` 之後用 `git branch -f fix/print-connect-timeout 904eb2a` 想指過去，
結果 exit 0 但 **`git show-ref` 剩返 `refs/heads/main` 一條** —— 即係 `-f` 把條 ref **剷咗**。
要再用 `echo <sha> > .git/refs/heads/fix/print-connect-timeout` 手寫重建。
所以：**git ref 操作一律要 `git show-ref` verify**，no-op 事少，靜默 delete 事大。已寫入 MEMORY.md。

## 同步（sync queue）：同一個 bug class，而且係全 app 最大嘅盲點

打印掃完之後掃同步，搵到**最嚴重嗰個**：同步 event 永久失敗之後，
**全個 app 零 UI 顯示**，而且永遠唔會再重試。

路徑（`src/lib/pos/sync-flush.ts`）：
- 網絡錯（fetch throw）→ 保留 `pending`、**唔加 attempts** → 會無限重試 ✅（設計啱）
- Server 拒收（`!result.ok`）→ attempts++，到 `MAX_SYNC_ATTEMPTS = 5` 標 `failed`
- 之後 doFlush 第 209 行 `if (attempts >= MAX) continue` **永久 skip** → 死咗
- 註釋自己寫「留低等人手 inspect」，**但個 inspect 根本唔存在**：
  - `pos-app.tsx` 有 `queue` state（L208）但**從來冇 render 過**（淨係 guard clause + server merge）
    —— 同 `printJobs` 一模一樣嘅病
  - `backoffice-sync-page.tsx` 讀嘅係 **server** `payload.syncJobs` —— 傳唔到 server 嘅
    event 當然唔會出現喺度（雞同鴨講）
- `resolveStoreId()` 嘅註釋寫住「server 會返 400，**寧願大聲失敗**」——
  實際行為係完全靜默，**連代碼自己宣稱嘅意圖都冇實現到**

順便喺 `shift-page.tsx` 搵到個獨立 bug（已修）：`forceSyncBeforeClose()`
`await fetch(...)` 之後**冇 check `result.ok`** 就照 `saveQueue(mark synced)` +
`setStatus("已同步 N 筆")` + `return true`。即係 server 返 400/500 都當成功，
啲單變咗 synced 就永遠唔會再重試。**交班係最需要確保資料落 DB 嘅一刻**。
（`sync-flush.ts` 嘅 doFlush 係有 check 嘅，得呢度漏咗。）

### 修法（三個檔）

1. `sync-flush.ts`：新增 **`POS_SYNC_FAILED_EVENT`**（淨係 UI 聽），喺 event 變成
   `failed` 嗰刻 dispatch。
   ⚠️ **唔可以 reuse `POS_SYNC_QUEUE_CHANGED_EVENT`** —— 嗰個俾
   `installPosSyncQueueAutoFlush` 當 trigger 用（聽到就 flush），喺 doFlush
   入面 dispatch 佢會**無限迴圈**。
2. `sync-flush.ts`：新增 `retryFailedSyncEvents()` —— attempts 歸零 + 轉返 pending，
   係永久 failed event **唯一嘅救命入口**（doFlush 自己唔會再揀佢）。
   呢度 dispatch `POS_SYNC_QUEUE_CHANGED_EVENT` 係安全嘅（會即刻 flush 一次）。
3. `pos-app.tsx`：聽 `POS_SYNC_FAILED_EVENT` + `failedSyncCount`，左下角加 amber 提示卡
   連「撳呢度重試同步」掣。用 **amber 而唔係 red** —— 資料安全留喺本機，只係未上到 DB，
   唔係即刻營運事故（同列印失敗嘅 red 分級）。
   順便將左下角改成垂直 stack（`flex flex-col gap-2`），因為兩種問題可以同時出現，
   兩嚿 fixed 會互相冚住。
