## 結帳頁「系統抹零」即時更新 fix（餐飲 pos-app.tsx）

用家報 bug：結帳頁輸入抹零金額後，應收額與小計唔即時更新，要等結帳落單後先見到，造成混淆。

根因：`rounding` / `due` 只喺 `changeDue` useMemo 入面算，結帳明細嘅「應收」行一直用 `paymentSummary.total`（未扣抹零）。

改動：
- `src/components/pos-app.tsx`：將 `rounding` / `due` 提升為組件頂層 const（`due = Math.max(0, paymentSummary.total - rounding)`）；兩個結帳明細 view（:7652 主彈窗 + :6626 訂單詳情彈窗）嘅「應收/剩餘需收」行改用 `due`；`changeDue` useMemo 改為 `received - due`。
- `src/components/order-discount-display.tsx`：`OrderDiscountRow` 加 `roundingAmount?` prop → 即時顯示「抹零 MOP -XX.XX」分項，並計入「合計優惠」總減免（用家要求「優惠」反映抹零）。
- 所有 `OrderDiscountRow` call site（pos-app 3 處 + local-orders-panel + quick-local-orders-strip）都補 `roundingAmount`（結帳用 live `rounding`；已落單 view 用 `order.roundingAmount`，令已結單都見到抹零，符合 docs/88「凡影響實收嘅調整都要見到」）。
- i18n：zh/en dict 加 `"抹零"` key（結帳明細行 label，同 input 嘅「系統抹零」區分）。

效果（用家例子）：消費 500、抹零 50 → 結帳明細即時出「抹零 MOP -50.00」+「合計優惠 MOP -50.00」，應收額即時變 MOP 450.00。

驗證：`npx tsc --noEmit` EXIT 0。

## 本地 screenshot 驗證快餐模式（唔成功，記低避免再撞）

`_i18n-shots2.mjs` 嘅 `enterWorkbench` 只識登入**堂食**（click「堂食收銀台」）；無 quick mode step。
試過自寫 `_i18n-quick-verify.mjs` 改 localStorage seed 走快餐流程，三條路都撞：

1. **種 `auth-session` + `operating-mode=quick` 嘅 key**：`loadOperatingMode()` 確實讀 `macau-pos/stores/<MID>/operating-mode`（storage.ts:1580），但 seed 咗呢條 key 畫面仍然出**堂食「Table overview」** —— 即係 mode 唔係單純由呢條 key 決定，要經過 register picker 流程先有效。
2. **唔種 `auth-session`**：得返 store-code 登入頁（「登入」+「安裝到主頁」），register picker 要先打 store code 先見到。
3. **offline-mode=1** + server 菜單：offline mode 攔咗 Supabase fetch，本地又冇種 `bootstrap` menuItems ⇒ 菜品區空，clickRegex 「加入$」永遠 false。
⇒ 結論：本地 puppeteer 跑 quick mode 截圖要起 full store-login + register-picker + 非 offline（或用真 Supabase env）嘅 harness，工程量唔抵。**quick mode 改 layout 嘅回歸測試靠 Vercel production 視覺確認**，或者用 `sweep`（堂食）排除冇 break 其他 mode。

另外：本機 `next dev` 開 port 3017 後，**taskkill /F /T 殺唔死**（process 仍 LISTEN，但 Stop-Process/taskkill 都 silently 失敗，估 sandbox 權限）。下次記得用 `mv .next .next.bak` 避開 build 清快速撞 sandbox 批量刪除保護。

## 報表「買貨明細」貨品細項全量彈窗（restaurant-daily-report.tsx + inventory-stats.ts + route.ts）

用家報：報表「買貨明細」卡嘅「貨品細項（按金額）」只顯示頭 5 行 +「共 N 款」，品項多時被截斷睇唔全。要求加個掣，click 開彈窗列晒所選時段篩到嘅全部貨品細項（唔受數量限制），並喺彈窗彙總總數。

根因回顧：`buildPurchaseSummary()` 原本就喺 `allItems.slice(0, PURCHASE_ITEMS_PREVIEW)`（=20）截斷 `items`，只留 `itemsTotal` 講「共 N 款」；常駐 summary 唔可以返全量（egress 考量）。所以全量清單要**按需**拉。

改動：
- `inventory-stats.ts`：`buildPurchaseSummary(receipts, fullItems=false)` 加 `fullItems` flag ⇒ `items: fullItems ? allItems : allItems.slice(...)`；`fetchPurchaseSummary(account, range, fullItems=false)` 加 `fullItems` 參數，`true` 時 query 加 `fullItems=1`。
- `route.ts` GET：讀 `fullItems`（"1"/"true"）→ 傳入 `buildPurchaseSummary(statReceipts, fullItems)`。其餘降級路徑（缺表/冇店戶）照用 `buildPurchaseSummary([])`。
- `restaurant-daily-report.tsx`：
  - import `type ItemStat`。
  - 狀態：`purchaseItemsModalOpen` / `purchaseAllItems: ItemStat[]` / `purchaseItemsLoading` / `purchaseItemsError` + `openPurchaseItemsModal()`（按需 `fetchPurchaseSummary(acc, range, true)`）。
  - 「貨品細項（按金額）」標題改 flex row，右側加「查看全部（共 {n} 款）」掣（只喺 `itemsTotal > 5` 出；loading 時變「載入中」）。
  - 新增彈窗（reuse `dishModal` overlay 風格）：header「貨品細項（按金額）」+「共 {n} 款品項」，body 全量 `purchaseAllItems` 表格（品項/數量/單價/金額，sticky header + `max-h-[55vh]` 滾動），footer「合計」+ `purchase.sel.total`。loading / error / 空 三態都有處理。
  - i18n：zh/en 加 `"查看全部（共 {n} 款）"` / `"共 {n} 款品項"` / `"貨品細項載入失敗，請稍後再試。"`（en 對應 View all (N items) / Total N items / Failed to load...）。重用 `"關閉"`/`"載入中"`/`"合計"`/`"品項"`/`"數量"`/`"單價"`/`"金額"`/`"本期間冇貨品細項資料。"`。
