## 登入 v2：裝置憑證改存 PIN 密文（commit `ce9be1f`，docs/161）

**根因**：`pos_bound_devices.refresh_token_enc` 存嘅係店主 session 嘅 refresh token。
- `signOut({scope:"local"})`（`session.ts:180`）會撤銷該 session ⇒ 憑證即死；
- `supabase-client.ts:52` `autoRefreshToken: true` 背景輪換但唔經 `resolveLedgerSession()` ⇒ DB 變舊票 ⇒ Supabase 判定 token 重用 ⇒ family 撤銷。

**改法（J 選方案 B）**：
- 0075 加 `owner_account` / `owner_pin_enc`（AES-256-GCM，key = `resolvePosTokenSecret()`）
- `mintSessionFromBoundDevice` 解密 PIN → `signInWithPassword()` → **全新獨立** session
- 刪 `syncDeviceBindingRefreshToken()`、`/api/pos/device/session` PATCH、`/bind` POST
- 授權搬入 `/api/ledger/login`（唯一同時有 storeId + 已驗證 PIN 嘅位）
- Secret 重用規則：出示得到現有 secret 就重用，出示唔到就發新（否則清 cache 後永久壞機）
- 裝置模式：已初始化嘅機唔問 8 位帳號，直接列身份卡（identities 支援 `{deviceId, deviceSecret}`）
- 移除「裝置授權」面板 → 撤銷收成員工權限頁底部細字連結
- `AuthGuard` 加 `pageshow`(persisted) → reload，修「按上一頁見到店主權限」
