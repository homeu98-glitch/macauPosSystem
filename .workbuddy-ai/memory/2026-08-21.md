## 快餐模式「查看」bug — 已修（2026-08-21）

user 澄清場景：堂食開咗單 → 轉快餐模式 → 撳查看 → 跳去桌面模式。佢要嘅 fix：快餐模式底下，無論張單係邊個模式開嘅，撳「查看」都只彈窗，唔好跳枱。

### 根因（追碼鎖定，非亂估）
- `activeTableId` 喺 boot 時會落到第一張真枱（`pos-app.tsx:444` `setActiveTableId((current) => current || data.tables[0]?.id || "")`）。
- `activeOrder` memo（`pos-app.tsx:665`）最後有 fallback：`activeTableId ? tableOrderMap.get(activeTableId)`（原 line 678）。
- 快餐模式 `activeTable` 已被強制成 synthetic `counter`（`pos-app.tsx:531`），但 `activeTableId` 仲係張真枱。
- 結果：快餐模式 boot/switch 後，`activeOrder` 經 tableOrderMap fallback 鬼祟載入張枱嘅堂食單入 workspace → user 見到「桌面模式」。
- `查看` 掣本身無問題（quick-local-orders-strip:64 + 查看本單 快捷入口:2683 都 call `setViewingOrderId` → 全局 modal `pos-app.tsx:3604`，無 mode gate）；「跳枱」係 boot/switch landing 顯示咗枱單，唔係 查看 掣 navigate。

### 改動（全喺 `src/components/pos-app.tsx`）
- `activeOrder` memo fallback 加 `!isQuickMode` 守門：`return (!isQuickMode && activeTableId ? tableOrderMap.get(activeTableId) : null) ?? null;`（dep 加 `isQuickMode`）。
- 效果：快餐模式 `activeOrder` 只經 `activeOrderId` resolve（落單時 `setActiveOrderId(order.id)`，line 1924，堂食+counter 都 set）→ counter 單照常顯；堂食枱單唔會再鬼祟入 workspace。撳查看 → 彈窗（viewingOrder modal），符合 user 要求。
- 無 in-app quick/dinein toggle（quick mode 只喺 login-screen:91 揀）；所以場景係 login reload，reload 後 activeOrderId 重置，fix 足夠。
