## 餐飲 WebUSB 實測確診：Windows driver 霸住 → Access denied

用戶實測測試打印：彈揀機對話框、揀完、冇紙出，status 報 `Failed to execute 'open' on 'USBDevice': Access denied.`

確診：Windows 將 USB 打印機 interface 綁咗 `usbprint.sys`，WebUSB `requestDevice` 揀機得但 `device.open()` 被 OS 擋 → Access denied。呢係 OS 層 block，唔係 code bug，ESC/POS / transferOut 根本未執到。

已改 `src/lib/print-webusb.ts`：`printToWebUsb` 嘅 catch 改用 `describeWebUsbError()`，detect "Access denied"/"open" 返中文引導（Zadig 換 WinUSB 或改用 print-bridge + USB）。`tsc --noEmit` 零錯誤。

**架構結論（重要）**：對 Windows + USB 收銀機，WebUSB 直印天生打不過 OS printer driver；**推薦路徑 = print-bridge + USB（連接方式 USB、填 Windows 印表機名、OS driver 行 RAW print）**。WebUSB 直印只適合 claimable 設備（部分型號 / Linux / Mac / 或 Zadig 換 WinUSB 後）。用戶係 Windows USB 機 → 應導佢行 print-bridge USB。

## 用戶追問：能否網頁打包、零安裝打印？

用戶測試機 = **WL-R80A**（USB 熱敏收銀機），已搵到 `WL-R80A-win` Windows driver，確認 USB 機要裝電腦驅動。用戶「唔一定全用 PC」（可能 Android 平板等）。

確實答案：
- **網頁唔能打包/安裝 USB 打印機 driver**：browser sandbox 冇任何 API 裝 kernel driver，呢個係 OS 層安裝，每部 PC 裝一次，唔係 per app / per web page。所以 USB-on-Windows「零安裝」喺 OS 層根本唔可能。
- **關鍵互斥**：裝咗 vendor driver（`WL-R80A-win`，正常打印必需）就等於 WebUSB 搶唔到 interface → Access denied。即 **vendor driver 同 WebUSB 喺 Windows 上互斥**。裝咗 driver 就唔好諗 WebUSB（除非 Zadig 換 WinUSB 拆走 driver）。
- **真正「web app 零額外安裝」嘅路（driver 裝好後）**：browser 原生 `window.print()` → 用 OS 已裝 driver 經打印對話框出紙。web app 唔裝嘢。代價：HTML/CSS 收據、無 ESC/POS 切紙/錢箱/廚房單控制，質量睇 driver + CSS。可加 `browser` connectionType 做呢模式。
- **全 ESC/POS（切紙/錢箱/廚房）喺 Windows** = print-bridge + USB（一次性本地服務）+ driver。
- **用戶「唔一定 PC」呢點係重點**：Android / Chromebook / Mac / Linux 通常無 driver 霸 interface → **WebUSB 可以真·零安裝**（Android Chrome 彈 USB 授權就 claim 到）。所以現有 LAN/USB/webusb + bridge 多模設計對多客端係啱嘅：Windows 行 bridge、Android 等行 WebUSB。
- 建議：Windows 測試機 → 裝 WL-R80A-win + print-bridge USB；同時可加 `window.print()` 模式做「app 零安裝」fallback。WebUSB 留畀非 Windows claimable 客端。

## print-bridge Windows 啟動步驟（用戶要嘅，已口頭畀）

1. 裝 Node.js（LTS）。
2. `cd print-bridge` → `npm install`（裝 `printer` + `iconv-lite`；`printer` 喺 Windows 要 build tools/python，裝唔到就 `npm install --global windows-build-tools` 或預編 node-printer）。
3. 裝 WL-R80A-win driver，睇「設定→印表機」個名（例如 `WL-R80A`）。
4. `npm start`（監聽 127.0.0.1:9222）。
5. POS 設置頁：連接方式=USB，USB 系統印表機名稱=上面個名；橋接 URL=`http://127.0.0.1:9222`（或 .env.local 設 NEXT_PUBLIC_PRINT_BRIDGE_URL）。
6. 撳測試打印 → 出紙即通。
開機自啟：Windows 工作排程器登入時跑 `node ...\print-bridge\src\server.mjs`。

## 用戶測試反饋：偵測 ≠ 印到、橋接狀態同 WebUSB 失敗無關

用戶截圖：偵測掣顯示「已綁定：USB Printer Port · 1A6BDE000000」（requestDevice 成功），但 status 仍係 Access denied（vendor driver 仲喺度，未做 Zadig）。橋接狀態「Failed to fetch」係因為未跑 service，同 WebUSB 失敗**完全無關**。

教訓：設定頁「已綁定」label 只代表瀏覽器授權，唔代表 device.open() 會通；UX 可考慮更清楚標示「已綁定 = 授權咗，仲要 Zadig 或切模式先印到」。

建議：先用「瀏覽器打印 (browser)」模式（已裝 vendor driver、web app 零額外安裝）過一張紙；唔過先考慮 print-bridge。
