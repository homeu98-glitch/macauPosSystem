## Vercel build 失敗修復 + bootstrap 設定上雲 sync（2026-08-17）

用戶貼 Vercel build log：`next build` TypeScript 失敗（exit 1），4 個 TS18047 `'supabase' is possibly 'null'`，全部喺 `src/app/api/salon/sync/route.ts` 4 個 helper（`upsertBooking/Order/PrintJob/Customer`）。

### 根因
`getSupabaseServerClient()` 回 `SupabaseClient | null`。4 個 helper 參數型別寫成 `ReturnType<typeof getSupabaseServerClient>`（含 null），函數內 `supabase.from(...)` 被 TS 判 possibly null。呼叫端 `if (supabase && ...)` 收窄唔會傳入 helper。bootstrap/state 兩個路由因 early `if (!supabase) return` 收窄，無此問題。

### 修法
- `sync/route.ts`：4 個 helper 參數型別改 `NonNullable<ReturnType<typeof getSupabaseServerClient>>`。

### 順帶接通「bootstrap 設定改動上雲 sync」gap（用戶確認要補）
原本 `saveSalonBootstrap` 只寫 localStorage + IDB kv，**冇 enqueue**，所以類目/項目/員工/場地改動只落本地、冇上 `salon_bootstrap_config` 表（多終端設定不同步）。
- `src/lib/salon/types.ts`：`SalonQueueEventType` 加 `"BOOTSTRAP_UPDATED"`。
- `src/lib/salon/idb.ts`：`SalonSyncQueueItem["entity"]` union 加 `"bootstrap"`；`eventTypeForEntity` 加 `bootstrap → "BOOTSTRAP_UPDATED"`。
- `src/lib/salon/storage.ts`：`saveSalonBootstrap` 尾加 `idbEnqueue({ entity:"bootstrap", refId:"bootstrap", payload: bootstrap })`（payload 係成個 bootstrap；flush 按 entity 去重只推最新）。
- `src/app/api/salon/sync/route.ts`：加 `upsertBootstrap()` helper（欄位映射同 bootstrap POST 路由：store_id/onConflict:store_id + 4 個 jsonb 陣列 + 數值/布林），POST loop 加 `BOOTSTRAP_UPDATED` 分支。
- 無 loop：saveSalonBootstrap 經 idbEnqueue → flush POST → 寫 DB；push 唔觸發 hydrate（hydrate 只開機一次），唔會迴圈。

## 第二輪 build 錯誤（Turbopack parse）：`??` 混 `||` 要括號（2026-08-17）

用戶再 push（commit c4d8372）後 Vercel 報 Turbopack build 失敗 1 error：`settings.tsx:802` `Nullish coalescing operator(??) requires parens when mixing with logical operators`。出自 `s.nickname ?? s.name || "(未命名)"`。TypeScript 檢查已過，呢個係解析期錯誤。

- 修法：`(s.nickname ?? s.name) || "(未命名)"` 加括號。
- 教訓：JS/TS 規定 `??` 唔可以同 `||` / `&&` 喺同一層次混用（除非加括號）。寫 `a ?? b || c` 一定掛，要寫 `(a ?? b) || c`。settings.tsx 其餘 `||` 都無同 `??` 直接混用（line 274 的 `chk && !chk.ok ? chk.reason ?? "" : ""` 中 `??` 喺 ternary 分支內，無混用，安全）。修好後應可過 build。
