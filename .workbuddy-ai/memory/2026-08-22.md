# 2026-08-22

## 修客人掃 QR 落到 demo 店（store 參數空 + 店名顯示）

用戶反映：喺自己店掃枱 QR，手機開咗 `/menu` 但係「demo 店（澳門店 A / macau-store-a）」嘅餐牌。兩層原因：

1. **餐牌內容（layer 1 真正 bug — 已修）**：手機係獨立設備，本地 `macau-pos/bootstrap` cache 係空 → `bootstrap = loadBootstrapCache() ?? mockBootstrap` 永遠 fallback 去 `mockBootstrap`（storeId=macau-store-a、storeName=澳門店 A），所以無論掃邊間店都睇 demo 餐牌。**backend 其實一早有 per-store 餐牌**：商家點餐機經 `GET /api/pos/bootstrap?storeId=<merchantId>` 讀 `pos_bootstrap_config`（pos-app.tsx:438 用緊，normalize 後寫本地 cache）。舊碼客人 scan 流程冇 call 呢個 endpoint，所以手機食咗 mock。用戶（2026-08-20）糾正：佢已經用 Ledger 登入、餐牌已從 Ledger sync 落 `pos_bootstrap_config`，kiosk/掃碼都要用商家點餐機內嘅餐牌。即 per-store menu backend **一直都存在**，只係手機未 call。
2. **落單路由都錯落 demo 店（實際 bug，已修）**：`kiosk-qr-panel.tsx` 舊碼讀 `loadAuthSession()?.merchantId` 做 storeId。但 kiosk 登入（`login-screen.tsx` mode=kiosk）淨係 `saveKioskDeviceBinding(...)`、`return` 之前唔 `saveAuthSession`（設計上「唔留 staff session」），所以「掃碼點餐」tab 度 `loadAuthSession()` 係 null → `storeId=""` → QR 變 `/menu?tableId=X&store=`（store 空）。客人手機 `storeId = binding?.storeId ?? scanStoreId ?? DEFAULT_KIOSK_STORE_ID`，手機無綁店 + scanStoreId 空 → fallback `macau-store-a`（demo）。連「呢張單落到邊間店」都錯。

**修法（layer 2 實際 bug）**：
- `kiosk-qr-panel.tsx`：storeId/storeName 改讀 `loadKioskDeviceBinding()`（kiosk 登入一定寫埋 storeId+storeName，可靠來源），fallback `loadAuthSession()`。URL 加 `&storeName=<綁店名>`。
- `use-kiosk-order.ts`：讀 `?storeName=`, 新增 `displayStoreName = binding?.storeName ?? scanStoreName ?? bootstrap.storeName` 並回傳。
- `order/page.tsx` / `menu/page.tsx`：頂欄店名改 `displayStoreName`（原本用 `bootstrap.storeName` / `binding?.storeName ?? bootstrap.storeName`）。order page 移除變成 unused 嘅 `binding` / `storeId` destructure。

**驗證**：`tsc --noEmit` 零新錯（剩已知 layout.tsx LayoutProps 誤報）；ESLint 0 errors（1 個預存 isPickup unused warning）。

**已完成（layer 1，2026-08-20）**：客人手機 `/menu` 現已按 `scanStoreId` call `GET /api/pos/bootstrap?storeId=<scanStoreId>` 攞商家點餐機同步落 `pos_bootstrap_config` 嘅真 menu（同 pos-app 員工端同一份）。`use-kiosk-order.ts`：
- 新增 `fetchedBootstrap` state；`bootstrap = fetchedBootstrap ?? loadBootstrapCache() ?? mockBootstrap`。
- 新增 `menuLoading = Boolean(scanStoreId) && fetchedBootstrap === null`；`menu/page.tsx` 載入閘 `if (!hydrated || menuLoading) return 載入中`，避免手機 flash demo 餐牌。
- `scanStoreId` 有值時 `useEffect` fetch `/api/pos/bootstrap?storeId=`，成功就 `setFetchedBootstrap(data)` + `setActiveCategory(data.categories?.[0]?.id)`；失敗保留 cache / mock fallback。
- kiosk 路徑（無 scanStoreId）完全唔變，照用本地 cache。

**下一步**：dev box `npm install && npm run lint && npm run build` 確認零迴歸後 push。手機依家顯示所屬店名、落單落正確 storeId、餐牌係商家點餐機嘅真 menu，唔再係 demo 澳門店 A。
