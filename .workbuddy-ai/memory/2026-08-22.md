## 5 項客人掃碼 / kiosk 體驗修復（2026-08-22）

用戶報 5 個問題，全部已改完，tsc 零新錯、eslint 0 errors（剩預存 warning）：

1. **手機菜單不能向下滾動** — 根因：`globals.css` 有 `body { overflow: hidden }` 禁咗整頁滾動，而 `/menu` 嘅菜單 `<section>` 無 `overflow-y-auto`，內容超出就睇唔到。修：`menu/page.tsx` 個 `<main>` 改 `h-[100dvh] overflow-hidden` + 頂欄/底 bar 加 `shrink-0` + 菜單 `<section>` 加 `overflow-y-auto`（內部自滾）。**唔動全局 overflow**（POS 平板需要）。

2. **客人落單後商店 POS 睇唔到新單** — 根因：cashier 收銀側嘅 state-pull（`/api/pos/state`）只喺 `[offlineMode, runtimeRefreshTick, queue]` 跑，`runtimeRefreshTick` 淨係 `backToTables` 時 bump，**唔係週期性**，所以一旦 Supabase Realtime 靜默失敗（anon RLS / Realtime 未啟用）就永遠睇唔到 kiosk 單（kiosk 單唔喺本機 localStorage，全靠 realtime / pull）。修：(a) `/api/pos/orders` GET 加 `?storeId=` 過濾；(b) `pos-app.tsx` 加 15s 週期 fetch `/api/pos/orders?storeId=merchantId` 並 `mergeOrderLists` 入本機 + saveOrders（server 端 service role 繞過 anon RLS）。配合上一輪 storeId 修正，收銀一定見到。

3. **落單成功號碼跟店內線下序號** — 之前 kiosk 用 `堂食/自取/外賣 + timestamp 後綴`，同店內完全唔連。修：落單前 `useKioskOrder.placeOrder` 向 `/api/pos/sequence` 攞同日序號，kind 對齊店內（`dine_in→pos`、`pickup→pickup`、`delivery→delivery`），storeId 用所屬店，咁就同店內線下單共用 `next_daily_sequence` 同一日序列表。`buildKioskOrder` 加 `localOrderNo?` 參數；fetch 失敗 fallback 返 timestamp 後綴。

4. **kiosk 落單成功頁無適配 iPad / 平板** — `/order` 嘅 `submittedOrder` 成功頁用 `max-w-md`（手機寬度卡），喺平板好窄。改 `max-w-2xl` + 放大 checkmark / 單號 / 字號，垂直置中。手機 `/menu` 成功頁唔變。

5. **菜品要顯示圖片（從 Ledger）** — `MenuItem` 加 `image?`；`LedgerMenuProduct` 加 `image?` 由 RPC 輸出解析（`image/image_url/photo/thumbnail/img/picture` 多候選）；`mapLedgerProduct` 帶 `image`；`normalizeMenuItem` 讀 `image`；`/menu` 同 `/order` 渲染圖片（有圖先 render，避免 broken img）。圖經 `pos_bootstrap_config.menu_items` 落到手機。注意：要商家重新從 Ledger 同步一次餐牌，DB 先會有 `image`，手機先睇到。

## 二維碼「太長，無法生成 QR」全部出現 + kiosk 單 POS 睇唔到（2026-08-22 後段，再排查）

用戶報：① kiosk 落單後 POS 睇唔到新單但單號正常；② 掃碼點餐 QR 全部顯示「太長，無法生成 QR（請用複製網址）」。

**② QR 根因（已修，確定）**：`src/lib/qrcode.ts` 自包含編碼器只支援 v1–5（byte mode EC-L 上限 = data 108 − 2 = 106 bytes）。而家 `storeId` 係 Ledger `merchant_id` UUID（36 bytes）+ 中文 `storeName`，URL ≈ 120–142 bytes 超過 106 → `encodeQrMatrix` 回 null → 全部顯示「太長」。
修法：(a) 編碼器擴充到 v6（size 41 / data 136 / ec 18，單 block，v1–6 唔使 version-info 模塊；alignment 中心 (34,34) 按標準 placement）；(b) `kiosk-qr-panel.tsx` 由 URL 移除 `&storeName=`（手機 `/menu` 已按 `scanStoreId` 去 `/api/pos/bootstrap` 攞返所屬店真名，`displayStoreName` fallback `bootstrap.storeName`，所以移除唔影響店名顯示，仲更準確）。移除後 URL ≈ 94–106 bytes，v5/v6 都穩陣。Node type-strip 測試確認 120 bytes URL → size=41（v6）OK、94 bytes → v5 OK。

**① POS 睇唔到 kiosk 單根因（硬化 + 診斷）**：happy-path 代碼其實正確——kiosk 落單 `store_id = binding.storeId (= merchantId UUID)`，POS 用 `authSession.merchantId` 過濾 realtime + 15s 輪詢 `/api/pos/orders?storeId=merchantId`，兩者應一致；`mergeOrderLists` / 顯示 tab 冇過濾。真兇係 **`/api/pos/sync` 靜默失敗**：舊碼 `if (supabase && events.length>0){...}` 唔 check upsert error，且 `supabase` 為 null（server env 缺）時都回 `ok:true` → kiosk 收到 200 → 顯示成功單號（所以「單號正常」），但單根本冇寫入 `pos_orders` → POS 永遠睇唔到。而家硬化：(a) `supabase` 為 null 且有 events → 返 503 + 明確 error；(b) 每個 upsert 收 `error`，有就收齊回 500 + 第一個 error message；(c) `submitKioskOrder` 解析回應，`!res.ok || body.ok===false` 就 throw 真 error（kiosk 改顯示真錯誤而唔係假成功）。
→ 部署後重測：若 kiosk 現顯示 error，就係 server 端 DB/env/schema 問題（relay 個 error 即可定位）；若仍顯示成功但 POS 唔見，就係 kiosk 綁店 merchantId ≠ POS 登入 merchantId（同店必須同一 Ledger 帳號），或 `pos_orders` 表喺共用 Supabase 項目未建（該表由 Macau-Ledger repo migration 建立，本 repo 只加 policy/publication）。

**改動檔**：`src/lib/qrcode.ts`、`src/components/kiosk-qr-panel.tsx`、`src/app/api/pos/sync/route.ts`、`src/lib/kiosk-order.ts`。`tsc --noEmit` 源碼零新錯（剩 layout.tsx 已知誤報）。下一步 dev box build + push。
