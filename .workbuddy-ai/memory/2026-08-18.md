## 緊急 Bug 修復：r.roles is not iterable

用戶回報美容院頁面載入報 `r.roles is not iterable`（「頁面載入時發生錯誤，你可以重試」）。

根因：`loadSalonStaff()` 讀**獨立** `salon/staff` 鍵；但 R2 嘅 `roles` 回填只寫咗 bootstrap 副本（`salon/bootstrap`）。對於**改呢版之前已 seed 嘅舊店家**，獨立 `salon/staff` 鍵仲係舊嘅 `role`-only 記錄（無 `roles` 陣列），`loadSalonStaff()` 回傳無 `roles` 嘅員工 → 任何 `.roles` 迭代（staff-list / settings / staff-detail / service-runner 銷售下拉 / wages）即 crash。

修復（`src/lib/salon/storage.ts`）：
- 加 `normalizeStaff(s)` helper：確保 `roles` 一定係陣列（舊 `role` → `[role]`，無值 → `["therapist"]`）。
- `loadSalonStaff()`：回傳前 `.map(normalizeStaff)`（防禦性，任何讀取都保證 roles）。
- `loadSalonBootstrap()`：回傳前 `b.staff = b.staff.map(normalizeStaff)`。
- `ensureSalonBootstrap` 升級塊 `if (changed)` 時加 `writeJson(SALON_STORAGE_KEYS.staff, existing.staff)`，將遷移後員工同步寫回獨立鍵（舊店家 standalone key 即時補 roles；首次員工編輯經 saveSalonBootstrap 亦會寫齊兩鍵，自癒）。

`tsc --noEmit` 過（僅 layout.tsx LayoutProps 環境誤報）。所有讀員工路徑（loadSalonStaff / loadSalonBootstrap = settings、service-runner、checkout staffMap、booking-form allStaff、staff-list、staff-detail）現已全部 normalized，crash 唔會再發。

用戶 dev box 待辦：`npm run build` 確認 + push。本地資料唔會遺失（normalize 只補 roles，唔改其他欄）。
