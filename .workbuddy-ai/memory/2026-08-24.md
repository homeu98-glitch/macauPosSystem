## bonjour 版本號 bug fix（2026-08-24 續）

用戶 `npm install` 報 `ETARGET: No matching version found for bonjour@^0.1.2`。

- **根因**：`bonjour` 喺 npm 已被接手，而家 only 有 `1.0.0 / 2.0.0 / 3.x`（latest 3.5.1），`^0.1.2` 呢個 range 從來唔存在；舊 `bonjour@1.2.0` 都已經 404（package 被重發，舊 version 落咗）。package-lock.json 入面根本無 bonjour 條目（lock 同 package.json 之前唔同步），所以 npm 係去 registry resolve 嗰陣 ETARGET。
- **修法**：改用有持續維護嘅 fork `bonjour-service@^1.4.4`（純 JS 零原生，mDNS API 兼容）。
  - `package.json`：`bonjour: "^0.1.2"` → `bonjour-service: "^1.4.4"`
  - `companion-server.mjs`：動態 import 由 `"bonjour"` 改 `"bonjour-service"`；`bonjourLib()` 改 `new bonjourLib()`（fork 嘅 default export 係 class，要 `new`）。
  - README 狀態表 library 名同步改 `bonjour-service`。
- **已驗證**：sandbox 跑 `npm install --ignore-scripts --dry-run` 成功（EXIT=0），`bonjour-service 1.4.4` 正常 resolve，`usb` 解析到 `2.18.0`。冇 ETARGET。
- **鎖注意**：lock 唔使手動改，npm install 會自己加 `bonjour-service` 並 prune 冇用嘅 entry。`npm ci` 唔使（lock 唔係 100% 同步）；用 `npm install` 就得。
- 用家部機真正 build 仍要 Python3 + VS Build Tools（serialport/usb native rebuild）。
