## Vercel build 紅：resolvePrintJobStatus 缺失（2026-08-24 續）

`next build` 喺 Vercel 掛咗 7 errors，全部同一 root cause：`Export resolvePrintJobStatus doesn't exist in target module [hub.ts]`。4 個 importer（pos-app.tsx:17 / print-center.tsx:8 / ledger-pos-bridge.ts:5 / salon/print.ts:11）import 咗佢，但之前 2026-08 刪 Printer Hub 時連 `resolvePrintJobStatus` 定義一齊刪走、冇更新 importer。

- **復原**：`git show d32513a^:src/lib/print-bridge/hub.ts` 搵返原本：
  ```ts
  export function resolvePrintJobStatus(networkOnline: boolean): PrintJob["status"] {
    if (isHubConfigured()) return "sent";
    return "pending";
  }
  ```
- **修正語意**：原本 Hub 配對就樂觀標 "sent"（Hub 自己派發）；但而家 dispatch 模型係 flush worker（dispatch.ts）只處理 `status==="pending"` 嘅 job。若新 job 標 "sent" 會被 worker skip、永遠唔出單 → 迴歸。所以改為**永遠回 "pending"**，交畀 worker 按 native/companion/relay 通道派發（無通道維持 pending 等下次 flush）。param 名 `_networkOnline`（未用，保留簽名兼容，同原本一樣個 arg 本嚟都冇用到）。
- 加返去 hub.ts（resolveJobPrinter 之後）。現 hub.ts 4 個 export：applyPairText / resolveJobPrinter / resolvePrintJobStatus / loadJsQr，齊晒 importer 所需。
- **教訓（重要）**：移除 module 嗰陣，除咗刪自己 export 嘅 symbol，一定要 `grep` 晒所有 `from "@/lib/print-bridge/hub"` 嘅 importer 確認冇人 import 緊被刪嘅 export（今次 `sendJobToHub`/`isHubConfigured` 有 grep 到，但 `resolvePrintJobStatus` 漏咗——因為佢係「共用 helper」被當係安全留低、其實定義連同 Hub 一齊無咗）。下次做類似 removal 要逐個 export 核對。
