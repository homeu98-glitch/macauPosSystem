## Salon 快速開單：走進/電話 toggle 改為有意義（方案 A）

用戶指出快速開單右上角「走進 / 電話」toggle 無實際分別（兩個 mode 都強制填 8 位電話），困惑點在於「走進都要電話」。解釋咗根因：電話係會員/客戶檔案系統主 key（ensureSalonCustomer(name, phone) 必定 run，用嚟開/連 customerId），所以舊規則兩 mode 都 mandatory；source 欄本意係記錄 intake channel 畀統計用，純顯示維度。

用戶揀方案 A：**走進 → 電話 optional；電話 → 電話 mandatory**。

落點 `src/components/salon/booking-form.tsx`：
- validate（~150）：電話 requirement 改 `source === "phone" && !/^\d{8}$/...`；deps 加 `source`（避免 stale closure）。
- handleSubmit（~191）：走進無電話時 `customer = null`，唔 call `ensureSalonCustomer`（避免 `phone:""` 孤兒檔案）；有揀會員仍照連 selectedCustomerId。
- 電話 label（~536）：走進顯「（選填）」灰字、電話顯紅 `*`。
- 電話 placeholder（~551）：走進「8 位數字（選填）」、電話「8 位數字」。
- 保留：電話 mode 電話 input sky-blue 底（強化「電話 mode 電話重要」視覺提示）。

驗收：`tsc --noEmit` 零非 layout 錯；div 平衡 40/40。

設計慣例備忘：salon `source` 欄取值 walk_in / phone / online_ledger（線上預約經 Ledger flow，快速開單 form 只露 walk_in+phone 兩個店內 intake）。本輪只改快速開單 form 嘅電話必填規則，source 欄本身語義不變（仍純統計維度）。

用戶 dev box 待辦：`npm run lint && npm run build` + push。

## Print-bridge HTTPS（Path ②，解決 mixed content）

用戶 keep Vercel，選 ②：幫 print-bridge 加 HTTPS，解決「HTTPS POS 網頁 fetch LAN HTTP bridge → Failed to fetch / health 紅」。

落點（全部 `print-bridge/`）：
- `src/server.mjs`：加 `import "dotenv/config"` + `node:https` + `node:fs`；env `PRINT_BRIDGE_TLS` / `PRINT_BRIDGE_TLS_PORT=8443` / `PRINT_BRIDGE_TLS_CERT` / `PRINT_BRIDGE_TLS_KEY` / `PRINT_BRIDGE_ALSO_HTTP`；handler 抽出 `handle(req,res)`，`/health` 回 `tls`+`port`；`startHttp()` / `startHttps()`（證書讀唔到 `process.exit(1)`）。
- `.env.example`、`start.sh`（載 .env 再 `exec node`）、`scripts/issue-cert.sh`（acme.sh DNS-01，預設 `bridge.yourdomain.com`，輸出 fullchain 到 `CERT_OUT_DIR`）。
- `package.json`：補 `dotenv` 依賴（否則 `npm start`→`node src/server.mjs` 會因 `import "dotenv/config"` 缺包報錯）。
- 新建 `docs/33-print-bridge-https-lan.md`：問題背景、方案圖、前置、Step1 公網 DNS + **店內 DNS 覆寫**（router/Pi-hole/dnsmasq/hosts）指 `bridge.yourdomain.com → 192.168.31.106`、Step2 acme.sh 發證、Step3 .env、Step4 start.sh、Step5 `curl -k https://IP:8443/health` 驗 `tls:true`、Step6 POS 設 `https://bridge.yourdomain.com:8443`、續期、FAQ、安全、無 domain 退路（自簽/Path① on-prem）。
- `print-bridge/README.md`：加「雲端 HTTPS POS 連 LAN bridge（Path ②）」段，指去 docs/33。
- `src/components/device-settings.tsx`：橋接 URL input 幫助文字 + placeholder 改 `https://bridge.yourdomain.com:8443`，並提 mixed content 要 https（輸入框本身 accept 任何 scheme，無限制）。

驗證：`src/lib/print-bridge/client.ts` `getPrintBridgeUrl()` 無 scheme 限制，且 deviceOverride 來源會跳過 localhost guard，所以 `https://...:8443` 會直通所有 /health /config /print /test-print。沙盒無 node_modules，用戶 dev box 待 `npm install && npm run build` 確認。

關鍵點：Let's Encrypt **唔可以**對 raw IP 發，必須 own domain；DNS-01 唔使 bridge 對公網開 80；店內 DNS 覆寫係重點（公網解析與 LAN 解析分開）。bridge 仍只係 LAN 服務，8443 唔好對公網開。
