# 2026-08-26 工作記錄

## 廚房單打印格式殘缺修復（companion renderEscPos，已修，要 rebuild exe）

用家報：落單經廚房打印機出單，但紙上只有「廚房打印機」字樣 + 菜名，數量/備註/桌號/單號全部遺失；螢幕 KitchenTicketPreview 有完整內容。

### 根因（companion-server.mjs）
- `renderEscPos(job, printer)` 係個極簡 stub：只印 `job.storeName || printer.name` 做抬頭（storeName 冇傳入 → fallback 去 `printer.name`＝「廚房打印機」），再 `for` 每 item 只印 `it.name`（有 note 才補 `  ${note}`）。**完全冇用 `quantity` / `specs` / `tableName` / `orderNo` / `createdAt`**。
- 雙重失誤：`/api/print` handler 原 `const { job, printer } = parsed` **冇收 `storeName`**（POS 經 payload.storeName 傳門店名，PrintJob 本身無 storeName 欄）→ storeName 被 drop → 抬頭錯。

### 修法（companion-server.mjs，非 git，要 rebuild）
1. `renderEscPos` 重寫對齊螢幕 `kitchen-ticket-preview.tsx`：門店名（bold center）→ 類型標題（廚房/收據/標籤，按 `printer.role`）→ 分隔線 → 枱號 / 單號 / 類型 / 時間 → 分隔線 → 每項 `name  x數量`(bold) + 規格(縮排 ·) + 備註(縮排 注：) → 分隔線 → 留底 footer。
2. `/api/print` handler 改 `const { job, printer, storeName } = parsed` + `if (storeName) job.storeName = job.storeName || String(storeName);` 注入門店名。
- `node --check companion-server.mjs` 過。receipt / salon 單共用同一 renderEscPos（泛型處理缺欄位，唔會 crash）。

### 部署
- 純桌面 companion 改動，**唔使改 POS / 唔使 push Vercel**。但 **必須喺 Windows dev box `npm run dist` 重 build exe** 先生效。
- 桌面版本升 **`0.1.7` → `0.1.8`**（按用家 standing instruction 主動報版本號；0.1.7 含 printLan 300ms drain + 版本號讀取，0.1.8 再加完整格式）。rebuild 後 Companion 視窗 / `/api/health` 顯 0.1.8，可核對 exe 含最新修正。
- 注意：Android APK 有自己嘅 EscPosRenderer.renderKitchenTicket（kitchen-ticket-preview.tsx 註解提過），今次只修桌面 companion 路徑；APK 側如要一致要另查 native.ts / EscPosRenderer。
