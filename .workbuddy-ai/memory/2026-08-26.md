## 62 · 「立即同步」vs「刪除全部訂單」行為釐清（2026-08-26，只分析未實作 · 待用家 confirm）

用家問兩點：①「立即同步」係咪直接從 DB 撈舊訂單落嚟？②「刪除全部訂單」係咪一次性連 DB 一齊刪？

### ① 立即同步 = 只上傳（push），唔撈 DB
- `pos-app.tsx:3054-3060`「立即同步」btn → `syncNow(queue)`（1835-1860）。`syncNow` 只 `POST /api/pos/sync` 推本地 queue 事件（ORDER_CREATED/UPDATED/DELETED、PRINT_JOB_CREATED、付款事件）去伺服器，標 `synced`；**完全無 GET / 無撈 orders**。
- 所以「舊訂單全部同步下來」並唔係呢個 btn 做嘅。真正「落」來自 `loadRuntimeState`（574-637）→ `GET /api/pos/state?storeId=X`（route.ts:24-26 讀 `pos_orders` Supabase DB，store 隔離）。觸發時機：mount / realtime `(re)subscribe`（`onResubscribed` 691-695，斷線重連都會）/ `backToTables`。
- 結論：用家見到嘅「舊訂單」確實係直接從 DB `pos_orders` 撈出嚟，但係經 backfill（reconnect/返枱面）落嚟，唔係「立即同步」btn 本身。網上 Supabase 模式 = 真 DB；mock 模式 route 返 `orders:[]`。

### ② 刪除全部訂單 = 設計上連 DB 一齊刪（一次性）
- `local-orders-panel.tsx:155-184` `handleDeleteAllOrders`：①`DELETE /api/pos/orders?storeId=X` → 伺服器 `pos_orders DELETE WHERE store_id=X AND online_order_id IS NULL`（route.ts:65-69）；②`saveOrders([])` 清本地；③filter 走 ORDER_* queue events 免重推；④dispatch `pos-orders-changed`。
- **範圍限制**：只刪 `online_order_id IS NULL`（店內線下訂單）；Ledger 線上單（online_order_id 唔空）按設計**保留**（免同會員餘額/線上單脫鉤）。btn 文案「刪除全部訂單」實際 = 「全部線下訂單」（toast 都寫「已刪除全部線下訂單」）。
- **落差 / 復活風險**：
  - A) Ledger 線上單被 exclude → 下次 backfill 照樣撈返嚟，用家以為「刪咗又返」。
  - B) `handleDeleteAllOrders` **冇寫 tombstone**（`deletedOrderIds`）——單筆刪除 `deleteOrderPermanently` 有，但「全部刪」靠 DB DELETE 完整。若 mock 模式（無 supabase）DELETE 返 `{deleted:0}` 當成功、DB 實際冇嘢刪（route.ts:58-61），本地清咗但 DB 仲有 → 下次 backfill 復活。
  - C) 其他終端唔會自動清（confirm dialog 已講明），佢哋 backfill 仍見到。

## 64 · 打印模板 spec/備註 字型大小不可調（analysis · 2026-08-26）

用家問：模板內 spec/備註 內容點解冇得調字型大小 / 物件尺寸。結論＝架構性寫死，唔係 bug、唔係個別設定鎖死。

- **樣式模型（資料綁定約束）**：`EscPosBlockStyle = {visible, size, bold, align}`（types.ts:217）只有 block-level `size`（s/m/l）。specs / note 唔係獨立 block，只係 `items` block 嘅 sub-line → model 根本冇 `subSize` / `specSize` 欄位，設計介面無嘢可 bind。
- **render 演算法**：`renderEscPosLines`（escpos-render.ts:35）將 items 成塊 emit 出一條 `{kind:"items", size:b.size}` — size 只 apply 到「菜名 + x數量」主行，sub-line size 冇傳落去。
- **三條 renderer 全部寫死 s**：
  - web 預覽 `escpos-preview.tsx:33,38` → spec/note sub-line `fontSize: SIZE_PX.s`（固定）。
  - 桌面 Companion `companion-server.mjs:267-268` → `textLine(spec, "s", false, align)`（固定）。
  - Android（未做）按設計會 mirror 同一寫法。
- **設計介面鎖定**：`print-center.tsx:443-444` designer 只提供 per-block `size` select（s/m/l），冇 spec size 控制項 → 商家改 items block size 只放大「菜名+x數量」，spec 仍係細字。
- **列印引擎限制**：ESC/POS thermal 只有 3 檔字型（`ESC ! n`，SIZE_BYTE s=0x00/m=0x20/l=0x60）；冇任意物件尺寸 / px 概念。「物件尺寸」對熱敏機無意義，只係字型大小。sub-line 寫死 s 係刻意（spec 係次要細節、細字易讀；避免每行 spec mid-line toggle 字型，慳指令+防錯）。
- **要啟用可調**：擴 `EscPosBlockStyle` 加 `subSize`（或 items block 專屬 subSize）+ 三 renderer 改讀 subSize + designer 加控制項（四處同步）。屬新功能，待用家決定。
