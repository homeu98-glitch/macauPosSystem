### Supabase Realtime 限制（查證 supabase.com/docs/guides/realtime/limits）

- **postgres_changes payload 上限 1,024 KB；超標時 `new`/`old` 只帶每個 ≤64 bytes 嘅欄位** → `template`/`items`/`content` 會被剝走。
- Broadcast payload：Free 256 KB / Pro 3,000 KB。Concurrent connections：Free 200 / Pro 500。Messages/s：Free 100 / Pro 500。Channels per connection 100。
- **⇒ 關鍵設計：Realtime INSERT 事件只當「叫醒訊號」，權威拎單一定要經 `pos_claim_print_jobs()` RPC 由 DB 直接攞完整 row。** 順便一併解決 event 遺失同多機爭奪。

### 方案要點（詳見 docs/96）

- 原子拎單：`pos_claim_print_jobs()` PL/pgSQL，`for update skip locked` + `attempts < 5` + `ttl > now()` → **物理上唔可能重複打印**。
- migration 0020：`pos_print_jobs` 加 `printer/kind/store_name/payment_method/total/qr/qr_url/copies/ttl/updated_at/claimed_by/claimed_at/attempts/last_error/finished_at`；新增 `pos_print_agents`（只存 `token_hash`）。
- 4 條 Vercel route（service_role）：`pair` / `claim` / `result` / `heartbeat`。

- 狀態機：`pending → printing → sent|failed`，`failed` 且 `attempts<5` 自動退回 `pending`。
