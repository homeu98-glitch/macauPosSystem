## 71f · ESC/POS 中文（Kanji）唔變大 — FS ! n 修（2026-08-27）

用家 confirm「直接幫你落碼」：出紙只有數字變大、中文字唔變大 → 確認係紙張 ESC/POS font 問題（非 web 預覽 bug）。

### Root cause（docs/71 §10）
熱敏機兩套獨立字庫：Latin/數字受 `ESC ! n`（0x1B 0x21 n，bit5=雙寬/bit4=雙高，`SIZE_BYTE {s:0,m:0x20,l:0x30}`）；**Kanji/中文受 `FS ! n`（0x1C 0x21 n）**，bit 位唔同 → `KANJI_SIZE_BYTE {s:0,m:0x01,l:0x03}`。中文多字節入機路由去 Kanji 字庫，`ESC ! n` 唔掂佢 → 只數字倍大。

### 落碼（兩個 renderer 都加 `FS ! n` when CJK）
- **Companion** `companion-server.mjs` `textLine`（~247-254）：加 `KANJI_SIZE_BYTE` + `hasCJK` regex；`setStyle` 後若 `hasCJK(text)` 額外 `push([0x1c,0x21,KANJI_SIZE_BYTE[size]])`。`node --check` ✅。legacy fallback `line()` 無 size 參數 → 略過（只影響非模板舊 job，加咗都 no-op）。
- **Android** `EscPosRenderer.kt` `Buf` 類：加 `FS=0x1C` 常數 + `KANJI_SIZE_BYTE` map + `hasCJK()`；`Buf` 加 `curSize` 字段，`style()` 記低，`str()/line()` 當 `hasCJK` 先 `cmd(FS,0x21,KANJI_SIZE_BYTE[curSize])` 再出字（順序 ESC ! n → FS ! n → text，同 Companion 一致）。legacy 路徑唔 call style → curSize="s" → FS ! n 0x00 no-op，安全。

### 已知風險
部分廉價機 Kanji 字庫固定 24×24 ignore `FS ! n` → 改 code 都唔會倍大中文（數字照倍大）。本修對支援 FS ! n 縮放嘅機有效。

- ✅ 確認有：`POSConnect.init/createDevice/connect/CONNECT_SUCCESS`、`IDeviceConnection.connect(String,IConnectListener)`+`sendData(byte[])`+`close()`、`POSPrinter.printText(String,int,int,int)`+`cutPaper()`+`setAlignment(int)`+`setCharSet(String)`。

- `net/SdkPrinter.kt`（新建 `object`）：`POSConnect.createDevice(type)` → `conn.connect(info,cb)`（suspendCancellableCoroutine 包 IConnectListener）→ `conn.sendData(EscPosRenderer.renderXxx(...))` → `conn.close()`。`print`/`testPrint` 兩入口；`initOnce` 雙檢鎖 guard `POSConnect.init`。
