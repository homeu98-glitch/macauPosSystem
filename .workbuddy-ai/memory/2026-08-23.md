## iPad / Apple 打印方案澄清（doc 41 補充）
- 用家問 iPad/Apple 點搞打印。結論：iOS 冇 WebUSB、冇 Web Bluetooth、冇 USB Host，單靠瀏覽器 LAN/USB/BT 全部打唔到。
- iPad 必須用原生 iOS App（WKWebView 外殼＋PosNative 等效 bridge），App 本身＝代理（iOS 冇 standalone localhost daemon，唔似桌面 QZ Tray）。
- transport 可用性：LAN ✅ raw socket（同 Android）；USB ❌；Bluetooth ⚠️ 只 BLE 或 MFi-classic；AirPrint 作基本小票 fallback（非 ESC/POS）。
- macOS 跟桌面 companion service，唔使特別處理；真正特例只得 iOS/iPad。
- 已更新 docs/41：新增 §3.7 iOS 一節、§3.6 對比表加 iOS 欄/行、§4.1 變「三個 build」加 iOS 列、§4.3 加 iOS 發佈細節、§5 加 iOS 分支說明、§6 結論補 iOS。

## 跨平台雙路徑打印設計（doc 43）
- 用家要求設計跨平台打印方案（桌面/Android/iOS），兩路徑：LAN 優先 + 互聯網 fallback；共用同一套架構與通訊邏輯。
- 核心：終端機本地代理 + 店內常開代理 = 同一套軟件兩種角色；中間 Cloud Print Relay（HTTPS/WSS，只轉發，店級隔離）。互聯網路徑不直接打打印機，經 relay 轉到店內常開代理用同一段 LanTransport 打印。
- LAN 失敗偵測靠「店內 LAN anchor」（mDNS `_macau-print._tcp.local` + storeId，或 pin IP）；打印機 socket 失敗但 anchor 在＝打印機問題，唔 escalate 去互聯網。
- 切換狀態機 ON_LAN ↔ RELAY，per-printer；healing 每 45s 重探，連續 2 次成功切返，防 flap；job 帶 ttl 60s。
- 三平台各 port 同一 coordinator 演算法 + 同一 LanTransport + 一個 WSS RelayTransport；Web 只 call print(job)。
- macOS 跟桌面；iOS 冇 daemon/USB host，App 本身＝代理，BT 限 BLE/MFi。
- 已新建 docs/43-cross-platform-print-dual-path.md（含架構圖、偵測條件、切換機制、三平台實作、安全、降級、階段）。
- 不推翻 doc 41 離線優先主路徑；常開代理只喺互聯網備援場景才需要。

## 三平台打包可行性評估（doc 44）
- 用家確認 APK/exe/App 打包打印功能是否可行。重點澄清：「中間人 bridge」分兩層——設備層 Hub（應移除）vs App 內 web↔native 通訊 bridge（三平台必須有）。
- 評估結論：Android ✅ 最簡最完整（APK 現有，擴 LAN/USB/BT）；Windows ✅ 可行但運維重（Electron exe，Authenticode 簽名＋USB 驅動＋自動更新）；iOS ⚠️ 可行但非全功能（USB 完全唔得、BT 限 BLE/MFi、App Store 審查＋企業分發成本）。
- 跨平台差異：ESC/POS renderer 共用（一套 code），transport 層各自 native（Android Kotlin / Windows Node/Rust / iOS Swift）；唔可以同一份打印 code 三平台通用。
- 已新建 docs/44-packaging-feasibility.md（總評表、三平台評估、打印功能差異、共同問題、落地順序）。
- 用家對「bridge＝中間人設備」概念仍有混淆，解釋時要分兩層講。

## 用家決定採用 local agent 方法
- 用家確認放棄舊嘅「HTTPS→遠端 HTTP Hub、內容放 URL」beacon hack（doc 41 問題③，脆弱），改採 local agent 方法。
- local agent 方法＝每個平台跑「Terminal Local Agent」原生外殼（載 POS 網頁＋提供打印 bridge），由佢用 OS 權限打 LAN/USB/BT；網頁只 call print(job)。
- 落地順序：Phase 0 定統一合約（PrintJob/connectionType 擴 lan|usb|bluetooth）→ Phase 1 Android(Sunmi) 擴 PosNative（最先）→ Phase 2 桌面 companion service（QZ Tray/localhost）→ Phase 3 iOS App（USB 缺口，最後）→ Phase 4 ESC/POS renderer 統一 → Phase 5 互聯網備援（Cloud Relay＋Stationary Agent，可選）。
- 最小起步：淨係有 Sunmi 就做 Phase 0＋1 已有 LAN 打印；其餘按實際終端/off-LAN 需求才做。
- 用家傾向要「列一次需要做嘅嘢」嘅清晰清單。
