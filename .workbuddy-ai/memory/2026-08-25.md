### 1. 無限重複打印「兩張自取單」+ 內容/格式不符（root cause + 修復）

- **現象**：下單後打印機不停重印兩張舊「自取單」；打印內容唔係當前單；格式同收據模板唔符。
- **root cause（resurrection bug）**：`src/components/pos-app.tsx` 嘅 `persistPrintJobs(nextPrintJobs)` 原碼係
  `setPrintJobs(nextPrintJobs); savePrintJobs(nextPrintJobs);`，而 `nextPrintJobs = [...新jobs, ...printJobs]`，
  其中 `printJobs` 係 **React in-memory state**。`flushPendingPrintJobs`（dispatch.ts）派發成功後只 `savePrintJobs`（寫 localStorage），
  **冇 update pos-app 嘅 `printJobs` state**（pos-app 冇 listen `pos-print-jobs-changed`；得 print-center 有）。
  所以 flush 將 job 標 `sent` 入 localStorage 後，pos-app state 仲係 `pending`。用家下次做任何動作（落單/退菜/退款）call `persistPrintJobs`
  → 將 stale `pending` state 寫返 localStorage → job 復活成 `pending` → flush 又印 → 無限 loop。
  兼且印嘅係舊單（stale content）→ 用家覺得「內容唔對」「格式唔符」（其實係印緊舊廚房單，唔係當前單 / 唔係收據模板）。
- **修法 A（`pos-app.tsx` `persistPrintJobs`）**：改以 `loadPrintJobs()`（localStorage 真源）合併，按 `id` 去重，
  已存在嘅 job 用 stored 版本（保留 `sent`/`failed` 狀態），stored 有但 incoming 冇嘅原樣保留。stale state 唔會再復活 pending。
- **修法 B（`dispatch.ts` `flushPendingPrintJobs`）**：加 module-level `isFlushing` 鎖，防止 PrintFlushWorker 2.5s tick 重疊
  （companion 慢時上一次 flush 未完，今次又 dispatch 同一 pending job → 雙印）。
- **驗證**：`npx tsc --noEmit` 全 repo 得 1 個 `layout.tsx` 已知誤報，其餘零 error。`node --check` companion/main 唔涉及。
