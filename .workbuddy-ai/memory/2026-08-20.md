## Native Print Agent APK Build 成功

沙盒環境原來有 Android Studio JBR（Java 21）+ Android SDK 36 + build-tools，成功 build 出 debug APK。

### Build 過程中 fix 嘅 3 個問題

1. **Kotlin plugin 衝突**：AGP 9.2.1 已內建 Kotlin 支援，再加 `org.jetbrains.kotlin.android` plugin 會報 `Cannot add extension with name 'kotlin', as there is an extension already registered`。Fix：`build.gradle.kts`（root + app）移除 `id("org.jetbrains.kotlin.android")`，只留 `id("com.android.application")`。
2. **kotlinOptions deprecation**：AGP 9.x 廢棄咗 `kotlinOptions { jvmTarget = "11" }`。Fix：改用 `kotlin { compilerOptions { jvmTarget.set(JvmTarget.JVM_11) } }`。
3. **Variable shadowing**：`MainActivity.kt` `printJob` 方法入面 local `val printer = ...PrinterCfgDto...` 遮蔽咗 class-level `private val printer = EscPosPrinter()`，令 `printer.printRaw()` unresolved。Fix：class field 改名 `escPosPrinter`。

### Build 結果

- APK 路徑：`print-agent-android/app/build/outputs/apk/debug/app-debug.apk`
- 大細：2.6MB
- 淨係 3 個 deprecation warning（databaseEnabled / onBackPressed），唔影響功能

## 🟡 sync-queue 無限增長 / 競態 · 已修（2026-08-20 下晝 · 已改；tsc 待 dev box 驗證）

根因（兩個 leak + 一個競態）：
1. flush 成功只標 `synced` 從不刪 → `syncQueue` store 越積越多（后端正常時都漏）。
2. **當前最致命**：真後端未到位，`pushSalonMutation` 永遠失敗 → 項標 `failed` 亦從不刪 → 每次 enqueue 都漲（舊 code 無 `attempts` 計次，failed 永遠留）。
3. 競態：`idbEnqueue` 每次 `void flushSalonSyncQueue()` 直接觸發，多個 flush 併發讀同一 queue + 併發 fetch 同 entity → 重複上推 / 寫覆蓋。

修法（`src/lib/salon/idb.ts`）：
- `SalonSyncQueueItem` 加 `attempts?: number`。
- `idbPatchQueueItem` 改為 await `tx.oncomplete`（flush 要按 id 順序刪/改，唔使飄）。
- 新增 `idbDeleteQueueItem`（await tx）。
- `flushSalonSyncQueue` 改走 **chain 序列化**：`flushChain.then(() => flushLoop())`；併發呼叫者排喺上一趟之後跑，新 enqueue 嘅 item 唔會漏推，又唔會同時開多個 flush（解決競態 + 重複上推）。
- `flushLoop`：每輪先清殘餘 `synced`（修舊 code 殭屍 entry）；`deleted===0`（全失敗）即收手，等下次觸發，避免離線無限重推；`MAX_FLUSH_LOOP=50` 安全閥。
- `flushBatch`：按 `createdAt` 取每 entity 最新一份（payload 已係整個陣列）只推一次；**成功即刪**；失敗 `attempts+1`，達 `MAX_SYNC_ATTEMPTS=5` 放棄刪除（數據已喺 localStorage / IDB kv mirror，唔會丟失），未達標 `failed` 等下次。

效果：無論后端在唔在，queue 都唔會無限漲；離線/未到位最多重推 5 次就 prune；上推唔會重複。⚠️ 沙盒無 node_modules，`tsc --noEmit` 待用戶 dev box 跑 `npm run build` 確認（預期只餘 `layout.tsx` `LayoutProps` 誤報）。

### 更正：線上訂單返結範圍收窄（用戶澄清：除了快餐）

用戶澄清上一條「線上訂單唔可以返結」太闊。正確規則：**純線上快餐/自取/外賣（counter / 未轉枱）唔可以返結；「線上堂食單轉到枱」已變喺店單，要可以返結；美容同理**。

原因（查 code 確認）：`bridgeLedgerOrderToPos`（`ledger-pos-bridge.ts:186`）對**所有**線上單都寫 `onlineOrderId`，dine_in 只係額外俾 `tableId` + `tableName`（經 `assignDineInTable` → `resolveTableMeta`）；轉枱後 `onlineOrderId` 唔會清走。而 `local-orders-panel` 用 `isLocalPosOrder`（=`!onlineOrderId`）過濾，令 dine_in 轉枱單連出現都唔會出現喺面板、更莫講話返結。

- **`src/lib/pos-orders.ts` `isReopenable`**：改為 `if (order.onlineOrderId) { const isInStoreDineIn = !!tableId && tableId!=="counter"; if (!isInStoreDineIn) return false; }` 然後 `return status==="settled"||"paid"`。即網上堂食轉枱單放行、counter/無枱線上單擋。
