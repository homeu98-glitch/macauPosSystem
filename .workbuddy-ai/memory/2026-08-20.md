# 2026-08-20 工作記錄

## Native Print Agent APK Build 成功

沙盒環境原來有 Android Studio JBR（Java 21）+ Android SDK 36 + build-tools，成功 build 出 debug APK。

### Build 過程中 fix 嘅 3 個問題

1. **Kotlin plugin 衝突**：AGP 9.2.1 已內建 Kotlin 支援，再加 `org.jetbrains.kotlin.android` plugin 會報 `Cannot add extension with name 'kotlin', as there is an extension already registered`。Fix：`build.gradle.kts`（root + app）移除 `id("org.jetbrains.kotlin.android")`，只留 `id("com.android.application")`。
2. **kotlinOptions deprecation**：AGP 9.x 廢棄咗 `kotlinOptions { jvmTarget = "11" }`。Fix：改用 `kotlin { compilerOptions { jvmTarget.set(JvmTarget.JVM_11) } }`。
3. **Variable shadowing**：`MainActivity.kt` `printJob` 方法入面 local `val printer = ...PrinterCfgDto...` 遮蔽咗 class-level `private val printer = EscPosPrinter()`，令 `printer.printRaw()` unresolved。Fix：class field 改名 `escPosPrinter`。

### Build 結果

- APK 路徑：`print-agent-android/app/build/outputs/apk/debug/app-debug.apk`
- 大細：2.6MB
- 淨係 3 個 deprecation warning（databaseEnabled / onBackPressed），唔影響功能
- 用 `JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"` + `local.properties` 寫 `sdk.dir`

### 仲未做

- 真機測試（裝 APK 到 Android 裝置 → 測試 LAN 打印）
- POS 端 `npm run build` 驗證無迴歸

## Request D：打印格式（票據 layout 適配）現狀確認

用戶問：「依家呢種方式，打印格式適配，係咪已經處理咗，定係未處理？」→ 結論：**未真正處理 / 得一半**。內容組裝做咗，但真正嘅票據 layout 引擎喺現行路徑冇被用到。

### 兩條路徑真相
- **現行 ACTIVE 路徑（有 wired）**：`dispatch.ts` / `salon/print.ts` → `sendJobToHub(job)` → `renderJobToText(job)`（hub.ts:105，**純文字**：header[加單/取消/桌號/單號] + items + 分隔線，冇 store name、冇時間戳、冇 per-role layout）→ APK `/api/print` 或 beacon → `LanHttpServer.runPrint` → `hub.printToIp` → `EscPosPrinter.printTextTicket`。呢條路只係把純文字包 minimal ESC/POS（init + 居中雙倍 title「POS」+ cut），**charset 強行 UTF-8，忽略每台 printer.charset（GB18030/Big5）**。
- **APK 完整格式化引擎（EXISTS 但 UNWIRED）**：`MainActivity.Bridge.printJob` 收 `{job, printer, kind}` JSON → `EscPosRenderer.renderReceiptTicket` / `renderKitchenTicket`（store name header、票種 label、單號/桌台、items、總計/支付、時間戳、cut、per-printer charset）。呢個先係真正嘅「打印格式適配」。

### 關鍵缺口
- POS 端 **完全冇 call `PosNative.printJob`**（src grep `PosNative|isNativeBridgeAvailable|dispatchJobToNative` → 零命中）；`src/lib/print-bridge/native.ts` 根本唔存在。`docs/36` 講「native 優先 → fallback HTTP」但冇落 code。
- 所以 `EscPosRenderer` 係 dead code 喺現行 flow；現行印出嚟嘅係「純文字 + 一個居中『POS』標題 + cut」，冇店名、冇時間、冇收據/廚房分版、charset 唔對。
- 次要：salon 收據把 `tableName` 當 customerName 塞，`renderJobToText` 會印出「桌號 {客戶名}」字眼錯。

### 修法（待用戶確認再做）
- 新增 `src/lib/print-bridge/native.ts`（`isNativeBridgeAvailable` / `dispatchJobToNative(job, printer, kind, storeName, paymentMethod, total)`），POS 經 `window.PosNative.printJob(JSON)` 落單。
- `dispatch.ts` + `salon/print.ts` 改為：native 可用 → `dispatchJobToNative`（走 `EscPosRenderer`）；否則 fallback `sendJobToHub`（純文字，舊路）。
