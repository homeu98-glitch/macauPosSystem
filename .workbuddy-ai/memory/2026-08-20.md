# 2026-08-20

## 餐飲返結帳：temp 枱流程（user 要求）

改咗返結帳（reopen）行為，符合 user 兩點要求：

1. 返結後唔取代原枱，改為喺原枱所屬 floor 新增一張 **temp 枱**（名 `返結 {原枱名}`），原枱保持空閒。
2. 返結後可直接「結帳」完成（唔使先送廚房）；結帳只改嗰條返結 record（唔新增 record），重結後原枱還原、temp 枱消失。

### 改動檔案
- `src/lib/types.ts`：`StoreTable` + `isReopenTemp`/`reopenOrderId`；`PosOrder` + `reopenOriginalTableId`/`reopenOriginalTableName`。
- `src/lib/pos-orders.ts`：`reopenPosOrder` 建立 temp 枱並搬 order（回傳 `tempTable`/`order`）；新增 `removeReopenTempTable()`（按 reopenOrderId 移除，寫入 localSettings.floors + dispatch `pos-local-settings-changed`）。
- `src/components/pos-app.tsx`：
  - `handlePosReopen` 成功後 `setActiveFloorId(temp.floorId)` + `setPosMode("order")` + `loadOrderIntoWorkspace(order, temp.id)`。
  - `confirmPayment.applyPaymentToOrder` 重結時還原 `tableId`/`tableName` 並清 temp 欄位，再 `removeReopenTempTable`。
  - `cancelOrder` / `refundOrder` / `partialRefundOrder` 結束時 `removeReopenTempTable(orderId)`。
  - `activeTable` memo 補 floors 回退（解析 temp 枱）。
  - `currentSettlementOrder` / `openSettlementModal` 容許 `reopened` 直接結帳。
  - 枱面 grid 標籤直接用 `table.name`（temp 枱名已含「返結」）。
  - deep-link 載入 temp 枱時 `setActiveFloorId` 鎖所屬 floor。
- `src/components/local-orders-panel.tsx`：返結後 `router.push` 用 `result.tempTable.id` 跳去 temp 枱。

注意：temp 枱只係本機顯示概念，唔 sync 去 server；返結本身無 push sync event，server 張單要到重結（ORDER_SETTLED）先更新。`mergeOrderLists` 留 updatedAt 較新者，本地返結單唔會被 server 舊 copy 覆蓋。
