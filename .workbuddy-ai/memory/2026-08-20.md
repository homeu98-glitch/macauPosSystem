## 修 QR encoder 掃唔到（src/lib/qrcode.ts）✅

用戶實掃報「掃唔到」。自寫 encoder 三個 bug，逐一用 jsQR（真實解碼器）+ qrcode 套件矩陣交叉驗證定位：

1. **z 字型 column-pair 方向**：loop `for (right = size-1; right>=1; right-=2)` 必須 `if (right===6) right=5;` 改動 **loop 變數本身**（唔係局部 col）。改動 loop 變數令後續倒退鏈出 `(5,4),(3,2),(1,0)`，否則會變 `(5,4),(4,3),(2,1)` 重複用 col 4、漏 col 0 → 解碼失敗。此即 Nayuki QR-Code-generator 嘅標準做法。
2. **format information bit 次序反轉**：bit14(MSB) 要放 (8,0)，bit0(LSB) 放 (0,8)（同 jsQR / qrcode 套件一致）。之前寫反（(8,0)=LSB）令 format 解碼錯。修法：copy1 `(8,0..5)=getBit(14-i)`、`(5,8)..(0,8)=getBit(5-i)`；copy2 `col8 size-1..size-8 = getBit(14-i)`、`row8 size-1..size-7 = getBit(6-i)`。
3. **（早前）mask 冇泛化 + 方向公式**：已喺上輪修正（maskCondition 8 款 + `upward=((size-1-right)/2)%2===0`）。

**驗證結論**：jsQR 對 4 個 case（v1 HELLO WORLD / 1234567890 + v3 兩條 order URL，含 alignment pattern）全部 `decoded === input` → PASS。v1 EC-L 淨係可以糾 ~3 個 codeword，如果資料錯 124 格根本解唔到，所以 jsQR PASS 即證 encoder 正確。交叉對比 show 嘅 DATA/FUNC diff 係對 library 矩陣 `reserved` 重建唔準嘅比較假陽性（自己 readback 同 expected codewords 完全吻合 64 180 132...），唔影響生產 QR。

**已清場**：verify-qr / cross-check / debug / check-data / check-mask / remask / dump / final-check / codewords 等臨時驗證腳本已全部 rm（依賴 sandbox node_modules，唔適合 commit）。
