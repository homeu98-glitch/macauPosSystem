## 餐飲返結帳：temp 枱流程（user 要求）

改咗返結帳（reopen）行為，符合 user 兩點要求：

1. 返結後唔取代原枱，改為喺原枱所屬 floor 新增一張 **temp 枱**（名 `返結 {原枱名}`），原枱保持空閒。
2. 返結後可直接「結帳」完成（唔使先送廚房）；結帳只改嗰條返結 record（唔新增 record），重結後原枱還原、temp 枱消失。

### 改動檔案
- `src/lib/types.ts`：`StoreTable` + `isReopenTemp`/`reopenOrderId`；`PosOrder` + `reopenOriginalTableId`/`reopenOriginalTableName`。
- `src/lib/pos-orders.ts`：`reopenPosOrder` 建立 temp 枱並搬 order（回傳 `tempTable`/`order`）；新增 `removeReopenTempTable()`（按 reopenOrderId 移除，寫入 localSettings.floors + dispatch `pos-local-settings-changed`）。
- `src/components/pos-app.tsx`：
  - `handlePosReopen` 成功後 `setActiveFloorId(temp.floorId)` + `setPosMode("order")` + `loadOrderIntoWorkspace(order, temp.id)`。
  - `confirmPayment.applyPaymentToOrder` 重結時還原 `tableId`/`tableName` 並清 temp 欄位，再 `removeReopenTempTable`。
  - `cancelOrder` / `refundOrder` / `partialRefundOrder` 結束時 `removeReopenTempTable(orderId)`。
  - `activeTable` memo 補 floors 回退（解析 temp 枱）。
  - `currentSettlementOrder` / `openSettlementModal` 容許 `reopened` 直接結帳。
  - 枱面 grid 標籤直接用 `table.name`（temp 枱名已含「返結」）。
  - deep-link 載入 temp 枱時 `setActiveFloorId` 鎖所屬 floor。
- `src/components/local-orders-panel.tsx`：返結後 `router.push` 用 `result.tempTable.id` 跳去 temp 枱。

注意：temp 枱只係本機顯示概念，唔 sync 去 server；返結本身無 push sync event，server 張單要到重結（ORDER_SETTLED）先更新。`mergeOrderLists` 留 updatedAt 較新者，本地返結單唔會被 server 舊 copy 覆蓋。

  - `voidOrderedItem` 改寫：只減購物車內「未退菜」線嘅數量，另 push 一條 `voided:true` 嘅記錄入 `voidedItems`；訂單 `items` 只存生效線、`voidedItems` 存退菜線 → 退菜唔計費、唔影響 `orderTotals`/送廚房。`upsertCurrentOrder` 落單時一併存 `voidedItems`。
  - 點餐介面「訂單明細」grid 喺生效線後渲染 `voidedItems`，紅色 `已退菜` 標籤 + 刪除線 + 原因；無 +/-、無退菜掣。

結帳（confirmPayment）/ 返結（reopenPosOrder）都 spread 原 order → `voidedItems` 跟單保留，重結 / 退款後仍睇到歷史。

注意：退菜記錄只喺本機單留低；`ORDER_ITEM_VOIDED` sync event 照舊 push（server 對帳用）。voidedItems 唔 send 去 server（server 用 event 對帳，唔需要明細行）。

## 餐飲退桌（void table）新功能（user 要求，only 堂食）

user 要新增「退桌」：客人入座後任何原因要走，哪怕點咗菜，店員一鍵將枱上所有菜作廢、枱返空閒。經討論確定設計後實作：

### 確認嘅設計決定
- 入口：枱位平面圖每張**占用中且非線上**堂食枱（status `draft`/`sent_to_kitchen`）卡面加紅色「退桌」chip，click 開確認對話框（填原因，復用 `cancelNotePresets`）。
- 只接 `draft` + `sent_to_kitchen`；**排除** `reopened`/`paid`/線上訂單（`onlineOrderId`）/快餐 counter。
- 已下單（sent_to_kitchen）嘅菜：照印廚房退菜單 + 推 `ORDER_ITEM_VOIDED` 事件；`draft` 未下單菜安靜放棄（唔印、唔推單項 event）。
- **記錄處理（user 揀「直接刪除」）**：推 `ORDER_UPDATED(cancelled)` 事件去 sync queue（server 標已退/已取消），然後由本地 `orders` 移除該單 → 枱因 cancelled 唔計入 `openOrders` 自動回落空閒。
- 權限：重用 `canVoidItem`（同全部退菜）。
- 注意：因 server 下次 sync 會將 cancelled 單 re-push 回本地 `orders`（只係 cancelled，唔佔枱），所以本地「刪除」係釋放枱位 + 唔留活躍單；server 側 audit 仍保留。floor grid 一定乾淨。

### 改動（全喺 `src/components/pos-app.tsx`）
- state：`voidTableRequest`(tableId|null) + `voidTableReason`。
- `findVoidableTableOrder(tableId)`：揾可退桌單（tableId!=="counter" && !onlineOrderId && (draft|sent_to_kitchen)）。
- `voidTable(tableId, reason)`：權限檢查 → 推單項 void event + 廚房退菜單 → 推 `ORDER_UPDATED(cancelled)` → `persistOrders` 移除該單 → 若 active 就清 workspace state → toast。
- 枱位 grid card 改 `div` 包 `button`（click=selectTable），voidable 時右上角加「退桌」chip（`stopPropagation` 開 dialog）。
- 仿 voidRequest modal 加退桌確認 dialog（標題「退桌原因」、原因輸入 + preset、確認 call `voidTable`）。
