## 第二輪：上線後商家仍報「庫存空白」→ 揭發缺欄檢測 bug

取證：生產 `GET /api/inventory/receipts?account=68189891`（Brewlab Coffee）回 `matched:false`（**非** 503 ⇒ expense client 已連、`shop_users` 真係冇列）。

**兩個全域 bug（任何環境都會中）**：
1. `provisionExpenseShopUser` 第一步 `selectByLoginId()` 喺 try/catch **外面**，且 select `id, external_shop_id`；live 若缺該欄 ⇒ `42703`/`PGRST204` ⇒ throw ⇒ 開通靜默失敗（連「已存在」都查唔到）。
2. `insert()` 只認 `code === "42703"`；PostgREST 對 `.insert()` 未知欄多回 **`PGRST204`** ⇒ 降級永不觸發。

**修法**：新增 `isMissingColumnError()`（42703 / PGRST204 / 訊息 regex，非缺欄照 throw）；`selectByLoginId` 缺欄降級只查 `id`；`insert` 用新 helper 降級寫基礎三欄；初始 select 包 try/catch 當「未搵到」交 INSERT+23505 兜底。
**測試**：19/19 pass（+4：初始 select 拋錯仍 INSERT／adapter 42703 降級 select id／adapter PGRST204 降級 insert／非缺欄照 throw）；tsc 0、eslint 0。

🔴 **仲有非程式問題**：開通只喺 `/api/ledger/login` 觸發。商家部署前已登入（session 喺 localStorage），按「重新整理」唔會再打 login ⇒ 要**登出再登入一次**先 fire。已寫入 doc §5.1。已 commit `68xxxxx` 待 push。
