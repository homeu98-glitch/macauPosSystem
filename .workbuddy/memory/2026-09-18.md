### 🔴 本輪學到的關鍵陷阱

1. **`npm test` ＝ `node --test`，唔認 `@/` 別名、唔行 bundler。**
   可測模組必須**零 import**（現有 `store-status.ts`、`date-range.ts` 都係咁）。
   所以 `runCloseGate()`（要 import hook 模組）一定要拆去另一個檔，
   否則 `close-gate.test.ts` 直接 `ERR_MODULE_NOT_FOUND: Cannot find package '@/lib'`。
   ⇒ **寫新 lib 模組時：純邏輯同有 import 嘅執行層一定要分檔。**

2. **`closeShift()` 有兩個 early return**（`forceSyncBeforeClose` 失敗、
   `!isPrintContentEnabled("shift")`）——後者**會完成交班**。
   任何「交班後必做」嘅動作必須排喺呢兩個 return 之前，否則靜默漏做。

3. **非 React 呼叫端唔可以 call hook** → 要 module-level export 函式（A 方案）。
   兩個 hook 都係 `useSyncExternalStore` module singleton，
   多掛 hook **唔會**多開 Realtime channel（同一份 state、同一條 channel）。

4. **`pos_store_status` 同 `pos_shifts` 嘅 default 方向要相反**：
   - `pos_store_status` 冇 row ＝ **營業中**（店主冇主動暫停過）
   - `pos_shifts` 冇 open row ＝ **真係未開工**（班次係事實記錄，冇記錄就係冇開過）
   兩者 fail-open 條件都係「**查詢失敗**」放行（唔可以一斷網全店停單）。

5. **`shop-closed` 同 `shift-closed` 唔可以撈埋**：前者係店主主動關門
   （叫客人等可能等到今日都唔開）；後者係未開工／已收工（叫客人「稍後再試」係有意義嘅）。

## 返結（反結賬）「42 vs 44」修復 + 返結標籤（程式碼完成，**未部署**）

**實案**：表嫂美食。店員結帳 44 → 撳返結 → 加 2 菜（盒×4/袋×4）→ 重結。
本機／收據 = 44，但訂單／報表／交班顯示 42。

**根因**：`src/components/pos-app.tsx` 嘅 `upsertCurrentOrder()` 嘅 `keepPaidStatus`
只豁免 `paid`，漏咗 `reopened`：
```ts
const keepPaidStatus = existingOrder?.status === "paid";   // 舊
```
返結單加菜時被寫成 `sent_to_kitchen` → `/api/pos/sync` 嘅「付款階段單向閘」
判 `paid-downgrade` → **整條 `ORDER_UPDATED` 拒收** → items 永遠上唔到雲，
只剩 `ORDER_SETTLED` 金額 patch（設計上唔重寫 items）→ 雲端「舊數量 + 新金額」。

🔑 **關鍵狀態集合事實**（`sync/route.ts`）：
- `TERMINAL = {settled, cancelled, refunded, partially_refunded}`
- `PAID = {paid, settled, refunded, partially_refunded}`
- `OPEN = {draft, sent_to_kitchen}`
- 🔴 **`reopened` 唔喺任何一個集合** ⇒ 寫 `reopened` 時 `isPaidDowngrade === false` ⇒ 放行。
  （所以修法係「保留 `reopened`」而唔係「改成 `paid`」。）

**修法**（`pos-app.tsx:2406`）：`paid || reopened`（單點改動）。
