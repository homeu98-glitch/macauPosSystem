## 🔴🔴 走數實案：收銀台「會員扣款」全額用餘額時**完全冇扣**（MOP 85）

**J 原話**：「我先是下了單, 然後我成功扣了款, 然後我又在那張桌台下了單, 然後我要結帳,
結帳的時候我是選了會員扣款… 他說是『客人已支付，完成訂單』… 然後我按下去後,
在 ledger 那邊只扣了我 75（掃碼嗰筆）, **沒有扣到我新下單的那一筆**。」

截圖數據：小計 **MOP 160**、客人已支付 **MOP 75**（綠）、剩餘需收 **MOP 0**、
**會員扣款 MOP 85**、支付方式選中「會員餘額 可用 MOP 219 · 本次扣 MOP 85」。

### 根因（`pos-app.tsx`）—— 判斷條件太闊
```ts
// L1982
const paymentSummary = { ..., memberDeduction,
  total: Math.max(0, payableBeforeMember - memberDeduction), };   // ← total 已減計劃扣款
```
```tsx
// 撳鈕 onClick（L6449）
if (paymentSummary.total <= 0 && paymentSummary.prepaidAmount > 0) {
  completeOnlinePaidOrder();   // ← 直接完成，唔會 confirmPayment()、唔扣款
  return;
}
```

**逐步重演**：`payableBeforeMember` = 160 − 75 = 85；店員選會員餘額 → `memberDeduction` = 85
→ `total` = 85 − 85 = **0** → 條件成立 → `completeOnlinePaidOrder()` → **MOP 85 走數**。

⇒ **`total <= 0` 唔等於「已付齊」** —— 因為 `total` 已減咗 `memberDeduction`（**計劃**扣款）。

### 兩個問題嘅答案（我自己查，唔應該問 J）
1. **「客人已支付，完成訂單」原意** = `completeOnlinePaidOrder()`：客人喺 Ledger／掃碼端

   只係判斷條件太闊。
2. **收銀台「會員扣款」只有「去結帳」才會真扣** ✅ ——
   路徑 = `confirmPayment()` → `runCheckout()` → `executeLedgerMemberCheckout()`（`merchant_apply_pos_txn`）。
   而 `total <= 0 && prepaidAmount > 0` 時**永遠去唔到呢條路**。

### 修正
新增 `isOnlinePaidComplete`（`paymentSummary` 之後）：
```ts
const isOnlinePaidComplete =
  !(useMemberBalance && memberDeduction > 0) &&          // ← 關鍵：有計劃扣款就唔算已付齊
  paymentSummary.total <= 0 &&
  paymentSummary.prepaidAmount > 0;
```

⇒ `memberDeduction > 0` 時一定落 `confirmPayment("會員餘額")` → 真扣款 ✅

  `ScheduledPickupChip`／`ScheduledPickupTimeText` 內部自動帶埋 `closed`，而且 `closed` 時**唔出相對時間**
  （所以再冇「已逾時 N 分鐘」）。⇒ **三處 UI 自動同步，caller 唔使改**。
