## 00:20 — PWA 更新機制（J 打算叫商家「開一次網頁 + 重新安裝 PWA」）

### 結論：可行，但**唔一定要重新安裝** —— 完全閂掉再開就夠
理由（查 `public/sw.js`）：
- **導航請求係 network-first**（`request.mode === "navigate"` 分支）⇒ 一開 PWA 就會拎**最新 HTML**。
- **chunk 係內容雜湊命名**（`/_next/static/immutable/chunks/<hash>.js`）
  ⇒ 新 deploy ＝ 新檔名 ⇒ SW 嘅 cache-first（`caches.match` miss）**照樣會去 fetch**
  ⇒ 新 JS 一定拎得到。舊 chunk 留喺 cache 但冇人引用。
⇒ **一個普通 reload 已經足夠**；重新安裝只係「更徹底」（順手清走舊 cache），成本低所以做都冇壞。

### 🔴 但有三個陷阱（要同商家講清楚）
1. **一定要「完全閂掉」，唔可以只切去背景**：切走再切返，個 window 從未銷毀
   ⇒ **舊 JS 一直留喺記憶體**，呢個正是嗰部 Mac 燒咗 904 MB 嘅原因。
2. **要閂埋 Safari / Chrome 嘅分頁**（唔止 PWA 圖示）—— 因為可能同時有普通分頁開住 POS。
3. **重新安裝唔會自動清 in-memory JS** —— 已開住嗰個 window 仍然係舊碼，要閂咗先。
   （SW 更新有 `skipWaiting` + `clients.claim`，但**換 SW 唔會令已執行嘅 JS 變新**。）
