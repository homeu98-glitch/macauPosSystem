## 🔴 挖出更深 bug：`paperColumnsFromSize()` 唔識標籤紙（docs/144 §2.11）

追問「商家要選什麼」時發現 —— **2.10 嘅紙寬限制其實一直冇生效**。

### 症狀
`print-jobs.ts` 標籤 job 靠 `Math.min(模板欄數, paperColumnsFromSize(printer.paperSize))`
截頂。但實作係：
```ts
return (paperSize ?? "").includes("58") ? 32 : 48;
```
`"60x40mm".includes("58")` = false → 回 **48**（80mm 票據機欄數）→
**打印機側永遠 48 → min() 形同虛設**。

實例：模板 100×75（61 字）＋ XP-235B（60mm = 34 字）→ min(61, 48) = **48**
→ 印刷 48 字落 34 字紙 → **嚴重溢出**。

### 第二個相關坑：同一尺寸兩種 id 寫法
- `types.ts` `LABEL_PAPER_PRESETS` = `"60x40"`（設計頁）
- `printer-models.ts` = `"60x40mm"`（型號表）

字串唔等 → `labelPaperPreset("60x40mm")` 搵唔到 → 靜靜跌去 62mm 預設（36 字）。
另外 `LABEL_PAPER_PRESETS` **缺咗** 30x20 / 50x40 → 已補。

### 修正：新增純模組 `src/lib/paper-columns.ts`（單一真源）
- 收據常數 48/32（`escpos-render.ts` 改為 re-export）
- `labelPaperPresetId()`（`"60x40mm"`→`"60x40"`；**`62mm`/`58mm`/`80mm` 唔剝**）
- `isLabelPaperSize()`（收據 58/80mm **唔算**標籤）
- `findLabelPaperPreset()` / `labelPaperColumns()` / `paperColumnsFromSize()`
- ⚠️ **分支次序**：標籤判斷要**行先**（`58x40` 標籤 vs `58mm` 收據都含 "58"）
- `escpos-template.ts` 改為轉發 + 保留公開 API

### ⚠️ 行為改變（要知）
| 打印機 paperSize | 修前 | 修後 |
|---|---|---|
| `"100x75mm"`（Zebra/TSC/漢印 預設） | 48 | **61** |
| `"62mm"` | 36 | 36 |
| `"58x40mm"` | 32 | 32 |

`100x75mm` 48→61 係修正（之前浪費一半紙闊）。

### 🔴 兩條新教訓
1. **「有註釋講明意圖」≠「實作真係咁做」** —— `print-jobs.ts` 嗰段
   「min() 會自動截頂」註釋寫得清楚，但被叫嘅函式根本唔識標籤紙。
   跨函式契約一定要有**測試釘住實際回傳值**，唔可以靠註釋。
2. **測試載入唔到嘅模組 = 冇測試守嘅死角** —— bug 存在咁耐係因為

   新模組如有日加 `@/lib/...` runtime import，測試會即刻爆 = 刻意護欄。
