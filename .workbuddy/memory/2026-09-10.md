## 「改咗但畫面唔變」根因：PWA service worker 快取（2026-09-10）
- 症狀：用戶報「交班紀錄／報表嘅訂單明細仍然唔係 table」。**代碼同線上部署其實都已經係新版**——`curl` 生產站 `macau-pos-system.vercel.app` 抽 `/_next/static/immutable/chunks/*.js`，`0h9z09ptysxnl.js`（/reports）同 `41m3aomzywbqe.js`（/shift）都揾到 `children:"狀態"` + `tfoot` `合計（`，舊卡片字串 `children:"應收金額"` 完全冇。
- **成因 ①（即時）**：長時間開住嘅 session（POS tab / iPad PWA）一直用部署前已載入嘅舊 JS；App Router **client-side 換頁唔會重新下載 bundle** → 要整個頁面 reload 先換到代碼。
- **成因 ②（系統性，已修）**：`public/sw.js` 舊版對**所有非導航 GET 一律 cache-first 且永不 revalidate**，包括 Next.js App Router 嘅 `?_rsc=` RSC payload 同 `/_next/static/**`；而 `CACHE_NAME` 寫死 `"macau-pos-v20-7-31"`（7 月 31 日起冇 bump）→ 舊 RSC payload 會一直指向舊 chunk 圖，**部署咗都會渲染舊組件**。另 `cache.addAll` 一條 404 就整個 install 失敗，舊 SW 永遠唔退場。
- **修法**（`public/sw.js` 已重寫）：`CACHE_VERSION = "2026-09-10"`（**每次部署前要 bump**）；導航 = network-first；`?_rsc=` = network-first + cache fallback；`/_next/static/**` = cache-first（內容雜湊、不可變，安全）；其他同源靜態 = stale-while-revalidate；跨域／`/api/` 一律 bypass；install 改逐條 `cache.add().catch()` 容忍失敗。
- **教訓**：呢個 repo「改咗 UI 但用戶仲見舊樣」第一件事唔係查代碼，而係**直接 curl 生產站抽 chunk 驗證實際派咩版本**（`grep -o 'src="/_next/static/immutable/chunks/[^"]*\.js"'` 再逐個下載 grep 特徵字串）。驗證手法可重用。
