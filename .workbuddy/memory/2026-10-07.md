### 🔴 核心不變量（守衛測試守住）
1. **永不覆寫**：`baselinePatch` 只喺 `hit.baseline_unit_cost === null` 時先有值。
   ⚠️ 唔可以因為「搵到更早日期」就改寫 —— 舊收據可能被刪／補登，令**已報告咗嘅上漲金額自己郁**。
2. **duplicate-key 補插路徑**（`ilike`）用 `hasBase` 守住，唔可以漏。
3. **冇基準 ⇒ `changeAmount: null`（唔係 0）**，`direction: "new"`，`isComparable("new") === false`。
   當 0 會令「漲價影響金額」合計細咗、睇落好似真係零影響。
4. **基準 ≤ 0 或 null ⇒ 當 new**，唔會出 `Infinity`／`NaN`。
5. **漲／跌金額分開加**（`totalUpAmount` / `totalDownAmount`），唔可以淨計 `Σ(changeAmount)`
   —— 咁漲跌互相抵消，睇唔出真實影響。
6. `unit_price <= 0` 唔做基準。
7. 同日多筆 → 揀**單價較低**者（保守，令漲幅偏細，唔會誇大呃老闆加價）。

## 清零既有 4 個 fail（2026-10-07 深夜 · J 指示「4 個既有 fail 修掉再一起上」）

### 🔴🔴 真 bug：duplicate-key 補插路徑靜默清空商家資料

**位置**：`src/lib/inventory-products.ts` 嘅 `duplicate key|unique constraint` 分支。

原本只 `select("id, baseline_unit_cost")`，然後直接寫
`last_purchase_date: row.last_date` / `last_supplier: row.last_supplier` / `category: row.category`
—— **冇**主路徑嗰個 `?? 現有值` 降級。而 `row.*` 可以係 `null`
（今次掃到嘅收據冇日期／供應商／品類）。
⇒ 走 duplicate-key 補插（併發／撞名）時，會把商家填好嘅供應商／品類**靜默清空成 null**。

**為何一直冇發現**：主路徑（`hit` 存在）行為正確；duplicate-key 只在併發／撞名才走。
呢個正是 P2 文件自己寫過嘅警語（「兩行一定要同 update payload 對齊」）嘅漏網之魚。

✅ **修法**：select 補齊 `last_purchase_date, last_supplier, category`，並用
`row.x ?? dupRows?.x ?? null` 逐欄降級（同主路徑逐字一致）。
✅ **回歸守衛已驗證有效**：暫時還原舊寫法 ⇒ 守衛即刻報錯。

### 測試寫得太死（守「代碼字串」而非「行為」）— 4 條

| 測試 | 壞喺邊 |
|---|---|
| `onMutated` | 斷言「**剛好 4 個**」，但 `runSync` 嘅 `silent ?: ` 兩分支各要 notify ⇒ 實際 5 個 |
| `duplicate-key…（用 hasBase）` | 斷言字串 `/hasBase/`，實作已改用 `shouldWriteBaseline()` |
| `syncFromReceipts 只喺 baseline NULL 時寫入` | 斷言逐字 `hit.baseline_unit_cost !== null`，實作已變 `shouldWriteBaseline(hit?.…)`；`const baselinePatch =` 實際有型別標註 |
| `一鍵同步要打同一支 sync API` | 斷言整句 `body: JSON.stringify({ store: merchantId, account })`，P2 加咗 `mode` 就爆（但契約冇壞） |

**⭐ 通則（已入坑）**：守衛測試要守「**行為不變量**」（缺咗會出咩事），
唔係「某一行代碼長點樣」。寫死一整句代碼 ⇒ 任何無害重構都爆，
而**真正壞掉時反而可能唔爆**。

### ⭐ 新工具：`functionBody(src, fnName)`（守衛測試用）

抽函式體。**唔可以「搵第一個 `{`」** —— 參數本身可能係 destructure／型別字面量：
`const runSync = useCallback(async ({ mode, silent }: { mode: "auto" | "manual"; silent: boolean }) => {`
⇒ 第一個 `{` 命中 `{ mode, silent }`。

✅ **策略**：由宣告處往後逐個 `{` 試配對（跳過字串／模板），**取內容最長者**
（參數／型別一定短過函式體），搵到 >100 字候選就收工。

🔴 **兩個坑**：
1. 本專案檔案係 **CRLF** ⇒ `stripComments()` 用 `^[ \t]*//.*$` 多行模式對唔上 `\r\n`，
   要**先 `replace(/\r\n/g,"\n")`**。
2. 唔可以用「>40 字就算函式體」嘅門檻 —— `{ mode, silent }: { mode: "auto" | "manual"; silent: boolean }`
   本身就 **44 字**，會誤中參數。
