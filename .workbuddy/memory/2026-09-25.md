## 20:1x Ledger 線下報表：第三輪修正 🔴 **clamp 權威必須在 SQL**

商家 UAT 回報：**單日對得上**（表嫂 09-24：27 張／MOP 1,847 ✅），但**超過 90 日嘅請求全部 503**。

### 根因（route 層邏輯錯，同 migration 無關）
route 用 `clampOfflineReportRange()` **先截斷**再傳落 RPC ⇒ SQL 收到嘅已經係 90 日內
⇒ 0058 回 `clamped=false` ⇒ 同 route 自己算嘅 `expected.clamped=true` 對唔上
⇒ `validateOfflineReportRpc` 回 `rpc-clamped-mismatch` ⇒ 503。

### 修法（用戶指名，3 處）
1. `route.ts`：RPC 傳**請求嘅原始** `p_from: fromParam, p_to: toParam`；
   `expected` 只保留作**核對回傳值**之用（雙保險，Ledger 亦會核對）；回應 echo
   `range: { from: validated.from, to: validated.to, clamped: validated.clamped }`。
2. `offline-report.ts`：`RpcValidation` ok 分支加 `from` / `to`；加型別檢查
   （`rpc-bad-range-type`）＋ `rpc-range-mismatch`；驗值後把 `raw.from` / `raw.to` 帶出去。
3. 加回歸 test：`offline-report.test.ts` 加 2 條（SQL 自己截斷後嘅值要收；缺 `from`/`to` 要拒）；
   `offline-report-guard.test.ts` 加 2 條源碼守衛（一定傳 `fromParam`/`toParam`、唔可以 `expected.from`；
   回應要 echo `validated.from`/`validated.to`）。

🔴 **migration 0058 冇改、亦冇重跑**（用戶明示「不用重跑 migration」）——0058 本來就係對嘅，
錯嘅純粹係 route 那邊「好心先截斷」。

### 通用教訓（已入 `docs/113` 對應節）
**「權威只可以有一個。」** 當上游（SQL）同呼叫端（route）都能做同一種正規化／截斷時，
呼叫端只可以「**預算一次嚟核對**」，**唔可以**「算完當真、再傳落去」——
否則上游見到嘅係已經被處理過嘅輸入，回報嘅「有冇截斷過」必然係錯，呼叫端就會永遠對唔上。
凡「上游會回 processed/flag 值」嘅 API，一律**傳原始輸入 + 用回傳值核對**。

## 庫存 UX：確認稿 vs 實作 落差覆核（J 問「為什麼UI 跟你畫的差那麼遠?」）

### 做法（可重用）
1. 用 `tools/mockup-canvas-fit.cjs <mockup.html> --shots --out <dir>` 把確認稿逐個畫面
   **重新 render 成 PNG**（要 `NODE_PATH=<managed node workspace>/node_modules` 才搵到 puppeteer-core）。
   ⇒ 以後答「mockup vs 實作」唔需要靠記憶，左確認稿右實作逐對比。
2. 實作畫面用 pos-ui-live-verify（dev server 必須 `localhost:3017`）截圖。
3. 產出物：`docs/mockups/inventory-ui-diff-2026-09-25.html`（**6 張圖 inline base64**，
   唔靠相對路徑 ⇒ 一定 render 到）＋ `docs/mockups/inventory-ui-diff-2026-09-25-preview.png`。

### 結論（三類）
| 畫面 | 判定 | 差異點 |
|---|---|---|
| ① 庫存主頁 | **忠實** | 付款方式 chips 實作列**主檔全部 9 款**（確認稿只列有資料嘅）；確認稿底部有虛線 footnote ＋「前往設置 →」，實作冇；實作**多**一段「庫存表」＋ 3 KPI ＋「＋新增庫存品」（確認稿主頁冇畫） |
| ② 新增收據 modal | **大致忠實** | chip 化 ✔、歷史品項快選 ✔；**未做**：收據日期 chips（實作用 `<input type="date">`）、品項數量 stepper（實作純輸入框）；品項一行式 grid 屬**簡化** |
| ③ 庫存・設置 | 🔴 **落差最大** | 確認稿＝**全頁** ＋ **4 個 chips**（供應商／品類／**庫存品**／**支付方式顯示**）＋ **兩個 panel 並排** ＋ 每行有 **⠿ 拖拽把手**同**「用過 N 次」** ＋ 頂部「返回庫存／保存」；實作＝**彈窗** ＋ **只有 2 個 tab**（供應商／品類）＋ 單 panel ＋ 無把手無次數 ＋ 只有「關閉」 |

### 落差成因（要記住，唔係 bug）
- 確認稿係**固定畫布 1180×880 嘅理想稿**，內建示範資料（7 張收據、12 供應商、6 品類）；
  實作要同時 render **空狀態**（0 收據 0 供應商）⇒ 睇落「空虛」。
- **支付方式顯示**：主檔歸 expenseRecorder（J 明令 admin panel 唔可搬入 macau-pos）
  ⇒ POS 端只可以**讀**（`GET /api/inventory/payment-methods`），所以得唔到「4 個 chips」嘅第 4 個。
- **庫存品**：功能有，但放咗喺主頁「庫存表」＋「＋新增庫存品」（`inventory-table.tsx`），
  **唔係**放喺設置頁 ⇒ 位置同確認稿唔同，唔係「未做」。
- 「使用次數／拖拽排序」確認稿畫咗但**未做**（需要後端加 count 或本地排序持久化）。

### 仍然未做／可以做
