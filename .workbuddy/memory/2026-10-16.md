## Ledger PR#40 提案審核：ensureLedgerSession 每次 setSession → GET /auth/v1/user 風暴
- 提案來源：Macau-Ledger PR#40（私有 repo 讀唔到，只有 J 貼嘅摘要）：晚市 iPad Safari 154 req/時；5 點修法（getSession fast path／≤5min refreshSession／每頁 1 次 setSession／聽 TOKEN_REFRESHED→realtime.setAuth／唔動 9 月守衛）。
- 已核實（本機 node_modules 實測，非推論）：
  - auth-js `_setSession()`：token 未過期 → `_getUser()` ⇒ **打 GET /auth/v1/user**（GoTrueClient.js:3042）；過期 → `_callRefreshToken`。每次呼叫必打。
  - `getSession()` ＝ 純記憶體讀取（Ledger client `persistSession:false` ⇒ memoryLocalStorageAdapter）；只有 expires_at 喺 90s 內（EXPIRY_MARGIN=3×30s）先會自動 refresh。
  - `refreshSession()` → POST /token?grant_type=refresh_token → 觸發 `TOKEN_REFRESHED`。
  - 🔴 supabase-js 2.112 bundle 內部已有 `_handleTokenChanged`：TOKEN_REFRESHED／SIGNED_IN／INITIAL_SESSION 且 token 有變 ⇒ 自動 `realtime.setAuth(token)`。realtime-js `setAuth` 會 push `access_token` 畀**已 join** 嘅 channel。⇒ 提案第 4 點 library 本身已做；仍建議顯式 `onAuthStateChange` listener 做升級保險。
  - autoRefreshToken ticker：30s tick、90s margin、只喺 tab visible 跑；hidden 停，返 visible 行 `_recoverAndRefresh`。
- 提案漏講／POS 獨有補充：
  ① `rewards.ts` redeemRewardGrants 嘅 `client.auth.getUser()` → 改用 JWT `sub` 本地解碼（`decodeJwtPayload` 喺 `lib/pos/realtime-auth-claims.ts`，零 import）。
  ② `ensure-customer.ts` 用 raw `getLedgerAccessToken()`（storage token，唔經 session 刷新）→ 改行 `ensureLedgerSession()`。
  ③ 跨分頁換帳號／另一分頁 refresh 過 ⇒ POS storage token ≠ client 記憶體 token 時要 bootstrap `setSession`（否則 B 分頁維持舊身份）。
  ④ **single-flight 必做**：7 個 mount 一齊 `restoreLedgerSession()` 會併發；refresh token rotation race 會令人誤登出。
- 方案（等 J 拍板先實作）：抽零依賴 `lib/ledger/ledger-session-decision.ts` 純函式 + node --test；`session.ts` single-flight 分流（bootstrap setSession／getSession fast path／≤5min refresh）；`supabase-client.ts` 顯式 onAuthStateChange→ensureLedgerRealtimeAuth。唔動 9 月 CLOSED／channel!==ch 守衛、onResubscribed、LAN print、pos_* realtime。請求數估算：154/時 → ~1-2/時。
