## 18:05 · 診斷：為何澳覓／mfood 單無法設定打印位置

用戶問「mfood 與澳覓訂單為何無法分別設定對應打印方式」——**純診斷，未改碼**。

### 根因（三個疊加）
1. **UI 冇呢個欄位**：`PosLocalSettings`（printZones / menuPrinterOverrides）＋`DeviceConfig`
   （只有 `shiftPrinterId`）都冇「平台訂單分區」。唯一「單據類型→機」binding 只有交班單。
2. **後端硬編**：`src/app/api/integration/grabber/orders/route.ts:157–166`
   `platformZone: null, defaultPrinterGroup: "kitchen"`，且唔傳 `menuItems`
   ⇒ `grabber-order.ts:483` `printerGroup: platformZone ?? menu?.printerGroup ?? defaultZone`
   ⇒ 平台單**全部品項**一律 `"kitchen"`。註釋已寫明「方案 A（平台訂單分區）屬 Phase 3」，未實作。
3. **平台菜名對唔到 POS 餐牌**（設計上係常態）⇒ `menu?.printerGroup` 永不存在。

### 路由機制（記住：唯一粒度係「菜品 → 分區」）
- `print-jobs.ts:239–296` `buildKitchenPrintJobs()`：取 `enabled && role==="zone"` 全部機，
  逐台 `matched = items.filter(it => !printer.zoneId || it.printerGroup === printer.zoneId)`，
  **`matched.length===0` ⇒ `continue`（冇 fallback）**。
- ⚠️ 對比 `ledger-pos-bridge.ts:209–358`：線上單**有 orphan catch-all**（孤兒品項塞入第一個 job）。
  兩條路唔對稱 —— 平台單冇呢層保護。

### 🔴 陷阱（要覆核一齊講清楚）
- 自己開「澳覓」「mfood」兩個分區再綁機 = **完全無效**（冇 item 帶呢兩個 group）→ 一張都唔印。
- 刪走／改名 `kitchen` 分區 ⇒ 平台單變 **0 張廚房單**（pos-app.tsx:4129–4137 會彈「分區對唔中打印機」）。
- **未搵到平台單嘅自動出紙路徑**：`isNewSelfOrder` 只認 `kiosk|scan`（`order-source.ts:29`），
  `online` 開關只管 ledger-pos-bridge ⇒ 平台單目前似只靠手動「打印廚房單／重打整單」。
  （此點屬推論，未在生產 log 驗證，下次要核。）
- `PosOrder["source"]` 型別聯集仍只有 `pos|kiosk|scan`，唔包 `aomi|mfood`
  （pos-app.tsx:5694–5701 已註明係刻意最小改動）。改型別要三處同步：`order-source.ts`＋badge＋呼叫端。

### 若要支援（建議方案）
- 擴充 `platformZone` 為 **per-source**（`{aomi?, mfood?}`），route 讀 per-store 設定傳入；
  加一格 admin UI（打印機綁定 → 平台訂單分區）。同時要決定「平台單會唔會自動出紙」。

  `isUniqueViolationError` 分支 **`ack(true)`**（route.ts:1702-1708）→ client 剷走事件 →
