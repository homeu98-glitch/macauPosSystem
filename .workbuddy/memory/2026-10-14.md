## 小平板 80% 整體縮放（同日第二輪，J 實機評「操作唔到」後）
- 根因：1000x600 CSS viewport 雖然踩入 min-900px 三欄，但每個 CSS px 物理比 iPad 闊 24% => 同級字/控件喺上面「大 24%」，600px 高分三欄每欄得 377px => 密度唔夠。
- 第一輪只改佈局唔縮內容（三欄出齊）J 仍話操作唔到 => 第二輪做內容縮放。
- zoom 方案已實測唔適用：body/root zoom .8 會令 flex-1+grid fr 爆闊（grid track 498->748、body scrollWidth 1250>1000 橫向溢出）。
- 正解：globals.css 加 media query (min-width:900px) and (max-width:1023px) => html{font-size:80%} —— rem 單位（字級/間距/控件高/欄寬）一齊縮 80%，dvh 同斷點（px）完全唔動；無 fixed 錯位、無橫向溢出（實測 scrollWidth=viewport）。
- 欄寬跟住改 rem：pos-app compact tier 13rem/15rem（iPad/desktop 的 lg/xl px 值唔變）。
- 手感驗收：40px 掣 -> 32 CSS px = 實體 7.2mm ≈ iPad 40px 的 7.3mm；一屏 6 張卡（原 3 張）；字 text-sm 14->11.2px。
- 全局影響：900-1023px viewport 下所有頁面都縮（/orders /settings /login /members 已 sanity check 無爆）；input 16px coarse 規則保持 px（縮過頭會觸發 iOS/Android 自動放大視口）。
- 驗收：6 case（1000x600 en/zh、900x600、600x1000 直、1080 iPad、1440 desktop）零 pageerror、零橫向溢出、iPad/desktop cols 數值完全不變；tsc 0 error、eslint 0 error。圖：docs/mockups/responsive-huawei-2026-10-14/scaled/。

  `min-width` 預設 = `auto`（內容最小寬度）⇒ 內裡有 `min-w-0` + `truncate` 都冇用，
  **外層 article 照樣被長菜名撐闊**。實測 row 281px vs 欄 166px（撐出 125px）；
  **iPad 一樣中招**：row 457px vs 欄 260px（撐出 209px）。中文介面一樣（持久化菜名唔翻譯）。
- 修：① `<article>` 補 `min-w-0`（正常 row + 已退菜 row）② 菜名行補 `min-w-0`
  ③ 副行補 `min-w-0 truncate` + `title` ④「加備註／折扣」動作列改 `flex-wrap`（英文 Add note + Discounts 喺 146px 淨闊會超出 11px，寧可排兩行都唔准裁）⑤ 鈕 compact `px-1.5 text-[10px]`
  ⑥ auto-print 行 compact 直排（英文「Auto-print on order/checkout」會疊住 pill）。
- 修後：row 146px（EN/中文）、btn 全部收喺入內（btnSpill -8）、零 spill、零 pageerror；
  **iPad 亦由撐出 209px 變成收喺欄內**（235px / 欄 260px）—— 係修 bug，唔係改 iPad 設計。
- 驗收方法教訓：上一輪我用 `row.width` 比較，冇用**絕對座標**（left/right），所以睇唔出撐出欄；
  ⇒ 驗「有冇超出容器」一定要比較 `getBoundingClientRect().right` 對**容器**的 right。
