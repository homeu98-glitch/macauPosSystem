2. 退款/作廢審計欄**有增量**（`refundedAmount`／`refundRecords.length`／`voidedItems.length` 任一變大）；
3. **且** `isReductiveUpdate`（qty 變少）**或** `incomingQty === existingQty`。

為何第 3 條不可省：退款之後**任何** snapshot 都會帶住退款欄 ⇒ 只憑第 2 條會令所有後續降級請求全放行。

🔴 **為何用「退款筆數」而唔用金額判退貨**：`refund_records` 係**單調**（只追加、不清空）⇒ 筆數增加係可靠信號；
金額可以係 0（全額折扣單退貨實退 0 元）⇒ 只用金額會漏判。

🔴 **`ORDER_SETTLED` 寫金額唔可以用 `!== null` 判**：`money()` 對缺值回 **0 而唔係 null**
⇒ 會無條件寫 0 蓋走雲端值。必須用 `key in obj` 逐欄「存在性」檢查（`settledField()` helper）。
