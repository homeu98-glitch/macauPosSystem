## 根治方案 `docs/111-sync-queue-outbox-plan.md`（已產出，未開工）
- 方向：queue 由「狀態流水帳」改做 **outbox** —— 上雲即刪、唔留 synced 墓碑；queue 只剩真待辦。
- 核心四條：A 入隊時按 `coalesceKey`（同 type + 同 entity，退菜再加 menuItemId）合併、**取代** flush 去重；B `doFlush` 成功改 `filter` 刪事件；C 移除 `pos-app.tsx:917` 嘅 server→client queue merge（外店事件流入 + 舊事件復活嘅根源）；D 加終態 `skipped`（`foreign-store` / `no-store`），切店時 `reconcileQueueScope()` reset。
- **去重跨 type 係真資料丟失**：最新者贏 → 離線時 `ORDER_SETTLED`（server 用 `.update()`，0 列唔報錯）或 `ORDER_ITEM_VOIDED`（server 根本唔處理）可以贏過 `ORDER_CREATED`，張單喺 `pos_orders` 蒸發。呢個比重複警告嚴重。
- 第三個 bug：`quick-order-fulfillment.ts:44/72` 寫 `status: readNetworkOnline() ? "synced" : "pending"` —— 線上時未 push 就標 synced（靠 legacyHealed 撞彩先上雲），要改一律 pending + notifyQueueChanged。
- 分期：P0（修 forceSync 覆寫 / syncNow 冇 check res.ok + counter 計真待推送）→ P1（outbox 四條 + GC，feature flag `macau-pos/sync-outbox-v2`）→ P2（server ORDER_SETTLED 兜底 + `pos_queue_events` 保留 7 日）。
