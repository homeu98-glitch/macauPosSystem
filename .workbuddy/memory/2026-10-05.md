### 根因（單一，結構性）

`pos-orders.ts:94 createReopenTempTable()` 建 `temp-reopen-<orderId>` 枱（名「返結 A01」），
但**只寫本機** `localSettings.floors`；`device-settings.tsx:633/909` 推上 server 時用
`stripReopenTempTables()` 剝走（`table-scope.ts` 註解講明：寫上 `pos_bootstrap_config.tables`
會**永久升級做真實枱** ⇒ 刻意唔上雲）。

⇒ 另一部機由雲端 backfill 到 `status=reopened` + `tableId=temp-reopen-xxx`，
但本機 `floors` 冇呢張枱 → `buildDisplayFloors()`（`display-floors.ts`）overlay 只疊本機獨有枱
⇒ **桌台總覽完全冇入口，商家喺該機無法重結**。A01 顯示空閒＝已搬去 temp 枱（設計如此）。

### 🔴 附带發現：更嚴重的隱藏 bug（未修，須記住）

`reopenOriginalTableId` / `reopenOriginalTableName` **完全冇上雲**：
- `pos_orders` 表由 `0043_pos_order_reopen_audit.sql` 起只有 `reopen_count` / `reopened_at` / `reopen_reason`
- 四條讀取路徑全部 **0 hit**：`pos-order-mapper` / `pos-order-row` / `/api/pos/orders` 內聯 mapper / `sync` baseRecord
- `sync/route.ts:1329` 只寫 `table_id`（= temp 枱 id），冇原枱欄

⇒ 後果：跨機重結時 `pos-app.tsx:4737/5030` `isReopenRestore = Boolean(targetOrder.reopenOriginalTableId)`
為 **false** ⇒ `confirmPayment` **唔會還原原枱** ⇒ 張單永遠卡喺 `temp-reopen-xxx`，
而該機根本冇呢張枱 → **枱面總覽永久空枱，單懸空**。違反記憶 §2 返結四鐵律嘅spirit。

### 🔴 R-1 最終解法（生產級，唔好改返）
新欄**獨立第二次 update**、`baseRecord` 零改動。理由：`baseRecord` 嘅 42703 降級清單係**硬編碼手寫**
（`legacyRecord` 逐個 `delete`），將新欄塞入 `baseRecord` 等於綁埋「新功能同步唔到」同
