## admin 讀唔到 Ledger 線上單 —— 架構性根因（2026-09-07 10:10）

用戶澄清：「線上」= **Ledger 嗰邊嘅線上單**，唔係 POS `pos_orders`（嗰邊全店只係得 3 張
`sent_to_kitchen`，全部同一間店 `d564b932-...`）。即係 **admin 報表完全冇讀過 Ledger**。

**兩個獨立 bug（已確診）**：
1. `loadOnlineByHour` effect（`restaurant-daily-report.tsx:~1110`）admin 模式 early return →
   `setOnlineOrders([])`。原因：`listMerchantOrders`（`src/lib/ledger/orders.ts:21`）第一行就
   `ensureLedgerSession()` 要**商戶 JWT**，admin 得 `adminSessionToken`，冇商戶身份。
2. `getMerchantReportSummary`（`src/lib/ledger/reports.ts:74`）signature 只係 `(range)`——
   **連 `merchantId` 參數都冇**，商戶由 RPC 內部 `auth.uid()` 推導。所以
   `restaurant-daily-report.tsx:1288` admin 模式直接 `setLedger({sel:null,d7:null,yest:null})`。
   → 會員充值 / 扣點 / 線上渠道 KPI 全部冇來源。

**關鍵限制**：`src/lib/ledger/` 全部係 **RPC-only**，冇任何 `.from("table")` 直讀
（grep 過：只得 `get_merchant_report_summary` / `list_merchant_orders` / `get_order_detail` /
`list_merchant_order_menu` / `list_merchant_customers` 等 RPC）。所以即使有
`getLedgerServiceClient()`（service-role，`src/lib/ledger/admin-server.ts`，讀 merchants 正常），
**都冇法直接查訂單表**——要嘛加 admin 版 RPC（帶 `p_merchant_id`），要嘛要先攞到 Ledger schema。

**已做（即時改善，唔改架構）**：admin 模式喺報表頂部加藍色提示條，明確講「管理後台只能顯示 POS
線下單，Ledger 線上渠道 / 會員充值扣點需要商戶身份」，避免顯示誤導性嘅 0。

**待辦（需要用戶提供）**：喺 Ledger Supabase SQL Editor 跑
`select table_name from information_schema.tables where table_schema='public' order by 1;`
攞到 schema 後，先可以寫 admin 版 RPC / 直查路線。

**另注**：`pos_orders` 全店只有 3 張單（全部 `sent_to_kitchen`、同一 store）→ 說明
