## 修復「測試打印」喺 web/PWA 環境誤彈「未配對 Companion」提示（2026-09-07 21:25，tsc+eslint 0 error）

**根因**：`device-settings.tsx:testPrint()` 自成一派嘅三段式（Native → Companion → 報錯），companion 通道**冇經 `shouldKeepCompanionAlive()` env gate**、亦**冇 fallback 去 relay**。結果：
- 純 web/PWA + 冇 companion URL：直接報「未配對 Companion 代理（請確認桌面 Companion 已啟動）」，但 web/PWA 開 desktop agent 根本無解，呢句提示誤導；
- 純 web/PWA + 有 stale companion URL：會去試打 5s loopback（companion-transport.ts 5s AbortController），然後報「Companion 測試打印失敗」；
- 真正出單路徑 `dispatch.ts:dispatchOneJob` 已正確處理——companion 過唔到 `shouldKeepCompanionAlive()` gate 就自動 fallback 去 relay，**所以實際單據出紙冇問題，純粹測試按鈕誤報**。

**修法**（`src/components/device-settings.tsx`）：
1. imports：加 `shouldKeepCompanionAlive`（companion）+ `getRelayTransport, isRelayConfigured`（relay-config）+ `PrintKind`（types）。
2. `testPrint()` 改成四段：① Native → ② Companion（`shouldKeepCompanionAlive() && isCompanionConfigured()`，同 dispatch 對齊）→ ③ Relay（`getRelayTransport().send({kind, storeName})`，同 dispatch 對齊）→ ④ 真係乜都冇時報「未配置任何打印通道：請到『打印中繼』配對雲端備援（relay），或於桌面裝置啟動 Companion 代理」。
3. 桌面 Companion 流程**完全唔受影響**——`shouldKeepCompanionAlive()` 喺原生殼 / `?companion=` 仍返 true，companion 通道行為照舊。
