## A. per-store token 實作清單（0051／0052／0053 已寫未部署）

- `0051`：Realtime 授權相關政策前置。
- `0052_pos_store_scoped_dual_claim.sql`：5 條政策改成
  `coalesce(auth.jwt() -> 'app_metadata' ->> 'store_id', auth.jwt() ->> 'store_id')`
  ⇒ 「Admin API 寫 app_metadata」與「舊式 top-level store_id」兩種機制都通，唔使再改 policy。
- `0053`：`pos_soldout` 加 `authenticated using (true)`（**必須** —— 冇佢 client 一升級就靜默讀唔到 soldout；
  呢張表要長期保留 anon，因為客人掃碼／kiosk 匿名讀，冇身份）。
- `POST /api/pos/realtime-bind`：身份**只由終端憑證（pv1）嚟**，只綁 `is_anonymous` 用戶，把 `store_id`
  寫入 `app_metadata`（只有 service_role 寫得入）。
- `realtime-auth.ts`：`signInAnonymously()` → bind → **refreshSession()** → `setAuth`；失敗冷卻 5 分鐘且永不 throw。
- `realtime-auth-claims.ts`：純決策模組，19 條單測。
- `supabase-client.ts`：改 `persistSession+autoRefreshToken: true`
  （否則每次 reload 建新匿名用戶 ＋ token 過期後**靜默失效**）。
- 4 個 realtime hook：一律喺 `.channel(` **之前** `await ensureRealtimeAuth`（Realtime 身份係**每條連線**，
  六條 channel 共用）；其中兩個係同步 module-level 函式 ⇒ 加 async 包裝 ＋ **世代守衛**防 channel 洩漏。
- 守衛檔 `src/lib/pos/print-and-order-realtime-guard.test.ts` 已擴至 **25 條**，含
  「`ensureRealtimeAuth` 必須出現喺 `.channel(` 之前」。
- ✅ 實測：匿名註冊 200、`role:authenticated`／`is_anonymous:true`／`app_metadata:{}`。
- 報告：`docs/reviews/per-store-token-assessment-2026-09-23.md`。
