### ✅ per-event upsert 優化（同日，商家要求）

**問題**：`sync/route.ts` 嘅 `pos_queue_events` upsert 喺 **per-event loop 之內**
（`for (const rawEvent of events)` → 每個事件一個 upsert）⇒ **N 個事件 ＝ N 個 PostgREST POST**。
實測（Supabase log）：該表 **150 次 POST／21 分鐘**，佔該表 212 次請求嘅 70.8%，**全專案請求數第一位**
（而 client 其實只發咗一個 `/api/pos/sync`）。

**改法**：loop 內只收集入 `queueRows: QueueEventRow[]`；loop **完之後**一次過去重 + 分批寫。
- 新檔 `src/lib/pos/queue-event-batch.ts`（零 import）：`uniqueRowsById()`（**後者勝**）、
  `chunkRows()`、`flushQueueEventRows()`（**client 由參數注入** ⇒ 可以用假 client 做行為測試）。
- `QUEUE_EVENTS_UPSERT_CHUNK = 100`（`payload` ≈1.7 KB／行 ⇒ 每批 ≤ ~170 KB，對 PostgREST body 上限留餘量）。
- 🔴 **一定要去重**：`onConflict: "id"` 之下同一批內重複 id → Postgres **21000**
  （`cannot affect row a second time`）⇒ **整批一齊失敗**、全部審計行冇寫入（只係 warning，唔會 throw）。
- 🔴 **一定要 `await`**（唔可以 fire-and-forget）：Vercel function return 後會被凍結，未送出嘅 write 靜默消失。

- 語義保持：loop 內任何 `continue`（業務拒絕／跨店事件）一樣唔留審計行；
